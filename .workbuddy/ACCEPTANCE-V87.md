## 这一轮回答的是哪句话

> 「我们只是把桌面上的图标整理移动到整齐的位置上，你现在是直接把桌面完全改掉了呢？」

先纠正一个前提：**腾讯桌面整理和我们是同一类做法 —— 都是自绘覆盖层**（有 Spy++ 实测的窗口层级佐证）。
真正的差别不在「谁画像素」，而在**能力从哪来**。所以这一轮做的是：把「我们自己实现的能力」逐块换成「Shell 原生能力」。

## 逐项验收

| # | 场景 | 动作 | 期望 |
|---|------|------|------|
| ① | **格子内空白右键** | 在任意格子空白处右键 | 弹出**原生桌面背景菜单**：新建 / 下一个桌面背景 / 显示设置 / 个性化 + 「Handy 桌面整理」子菜单 + 你的全部第三方扩展（VS / PyCharm / Trae / Code / Everything…） |
| ② | 新建文件夹 / 文本文档 | ①里点「新建 → 文件夹」 | 文件**真的建在桌面**，立刻出现在「未归类」竖条，并**自动进入改名框**可直接打字（对齐 Explorer） |
| ③ | **Ctrl + 右键** | 格子/桌面空白 Ctrl+右键 | 弹 Handy 自己的菜单（Shift 仍归系统的扩展动词，我们没抢） |
| ④ | **F2 改名** | 选中一个条目按 F2 | 进入改名框；回车生效，Esc 取消 |
| ⑤ | **单击两次改名** | 在条目上单击 → 停半秒 → 再单击 | 进入改名框（间隔需在 350ms–1500ms 之间，比双击慢、比两次独立点击快） |
| ⑥ | 改名不改扩展名 | 把「笔记.md」改成「笔记2」 | 磁盘上是「笔记2.md」（要改扩展名就自己打全） |
| ⑦ | **排序方式** | 格子标题栏右键 → 「排序方式：…」 | 循环切换 自定义顺序 → 按名称 → 按类型；重启后保持 |
| ⑧ | 条目右键 | 文件/文件夹上右键 | **本来就是真原生菜单**（`IContextMenu`），含 WinRAR 等第三方扩展 —— 这条没变，用来对照 |
| ⑨ | 改名不搬文件 | 试着把名字写成含 `\` 的 | 直接拒绝（「改名」与「搬文件」只隔一个反斜杠，绝不放行） |

## 一条必须说清的取舍

**格子外的「真桌面空白」区，浮层是点击穿透的**：那一区的右键会落到 **Explorer 自己弹的原生菜单**上，
所以 V81–V86 那套「借出桌面」机制**还留着**、只为这一区服务。

- 格子内空白 / 条目 → 我们弹的菜单（全原生）
- 格子外空白 → Explorer 自己弹（+借出）

如果你测下来**格子外那一区还是觉得闪/要刷新**，那就需要再做一步：拦住穿透、让整屏都走我们的菜单
（要动 `set_ignore_cursor_events` 的命中模型，风险不低，我留着等你一句话）。

## 已知未做

  要新增 COM 依赖手写 `IDataObject`（`CF_HDROP`）+ `DoDragDrop`；难点是 `DoDragDrop` 是模态循环，
  而我们自己的窗口也是 Tauri 的 `IDropTarget`，必须显式拒绝自身否则自吞。
  更要命的是 **agent 会话启动不了 GUI**（挂死在启动早期），我无法真机验证 —— 做坏会把现在能用的
  指针拖拽一起搞挂。所以留给你在本机验收时推进。
- 排序暂不提供「按大小 / 按修改日期」（要给每个条目 `stat`，不值当）。
- 「查看 / 刷新」不在 `IContextMenu` 里（是 DefView 的 `IShellView` 菜单），查看方式早在 V51 就有了（图标/列表）。

## 关键取证（本轮最值钱的一条）

`src-tauri/examples/bg_menu_dump.rs` 实测三条取菜单路线：

| 路线 | 做法 | 结果 |
|---|---|---|
| `SHGetDesktopFolder()` → `CreateViewObject` | **背景菜单** | ✅ 16 项，含「新建」「显示设置」「个性化」+ Handy 子菜单 |
| `SHParseDisplayName(桌面目录)` → `BindToObject` → `CreateViewObject` | 目录背景菜单 | ✅ 15 项，含「新建」，但少桌面专属项 |
| `SHCreateItemFromParsingName` → `BHID_SFUIObject` | **条目**菜单 | ✅ 36 项，只有「打开/复制/属性」，**没有「新建」** |

另：第一次尝试的 `SHGetKnownFolderIDList(FOLDERID_Desktop)` + `BindToObject` 报 `E_INVALIDARG` ——
**FOLDERID_Desktop 的 PIDL 就是命名空间根本身，Root 没有父可绑**。这条已写进回归守卫。
