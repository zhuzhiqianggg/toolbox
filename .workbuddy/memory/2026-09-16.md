### 2. `platformOf()` 的关键细节（回归重点）

**不能粗筛 `/[LW#]/`** —— 月份别名 `JUL` 含 `L`、星期别名 `WED` 含 `W`，粗筛会把最普通的
`0 9 * * WED` 误报成「Quartz 专用」。假警报会让人开始无视提示，比不提示更糟。
实现按「逗号切分后的**整段**」精确匹配 `L` / `5L` / `15W` / `1#2`。
另：未知宏（如 `@everyday`）原先返回 `form:'standard'` 导致不报警 → 改回 `'macro'`。

### 3. 文本处理台（Phase 1）

- 逻辑全在 `src/lib/textlab.ts`（纯函数，无 React/DOM），界面 `TextLab.tsx` 只收参显示。
  `LINE_OPS` 是**数据驱动表**（20 项 / 5 组），`applyLineOp` 是唯一 switch —— 新增行操作 = 加一条数据 + 一个分支，界面与回归自动覆盖。
- **换行风格必须全程带着走**：切行统一吃 `\r\n` / `\r` / `\n`，拼回按原风格还原。
  直接 `split('\n')` 会在 Windows 文本行尾留 `\r`，于是「去重」把 `a` 和 `a\r` 当成两行 —— 这类工具最经典的假 bug。
- 界面是**就地改写 + 30 步撤销栈**，不是「左输入右输出」：本机窗口最小 640px，左右分栏各挤一半；
  真实用法是「粘贴 → 操作 → 复制」，中间态没有保留价值。
- 四个页签：查找替换 / 行处理 / 列与包裹 / 统计与换行。带示例条（Nginx 日志、IP 列表、SQL IN、正则提取 IP）。

### 4. 响应式审计：把「口头要求」变成可复跑工具

**关键认知：只看溢出会漏掉所有真缺陷。** V23 抓到的两处，`ox` 全程为 0：

1. `CalendarPanel` 的 42 格网格挂 `flex-1` → 窄窗口下被压进「剩余高度」，680px 时日历只显示到 **20 号**；

**统一修法**：`lg` 以下一律单栏、各面板按内容高度排布、滚动交给外层内容列；
一切 `flex-1` / `min-h-*` 加 `lg:` 前缀关进宽屏。复跑 **30 页面 × 3 视口 = 0 溢出 / 0 裁切 / 0 重叠**。

> **flexbox 教训（与 V22 §1.8.1 是一体两面）**：`flex-1`（`flex-basis: 0%`）在**auto 高度父容器**里
> 不是「撑满」而是「可被压缩到 0」。要撑满必须给父级明确高度；给不了就内容自然排布 + 外层滚动。

### 2. 密码：符号不连排要「构造」，不能「修补」

- **先合并重复实现**：组件内联那份与 `@/lib/passwordGen` 各有一套近似逻辑（V24 遗留）→ 删内联（−5576 字符），
  只留 `passwordGen.ts`。**同一份逻辑写两遍，改一处只治好一半。**
- 默认符号占比 **100% → 25%**，界面新增「符号不连续」开关（默认开）。
- 「不连排」若用「生成后扫一遍、发现连排就换位置」实现 → **死循环 + 取值偏置**。
  改用性质构造：**可用槽位按奇偶分两组，只从一组抽样 → 结果两两必不相邻**（可证、无循环、无偏置）。
- 容量上限 `separatedCapacity(n) = ceil(n/2)`：40 位想塞 20 个符号**做不到**（首尾被占后只剩 38 个候选位，
  同奇偶最多 19）→ **收敛并在 notes 里说明原因**，绝不悄悄少给。
- 回归 86 条，期望值用**独立公式**表述（`expectedSymbols = min(max(1, floor(len·ratio)), separatedCapacity(len−2))`），
  不复述实现 —— 否则实现错了测试跟着错。

### 3. 正则库：实测 16/30 条零命中

- 根因是**语义错配**：一批「整串校验」（`^…$`）条目配了**多行样本文本** → 永远不可能命中。

### 3. 修掉的 6 处真缺陷（全部先写失败断言、再改实现）

最高危的一类是「**不报错、只给错答案**」——用户看不到任何异常，只会得到一个错的结果：

1. **URL「主机:端口 被当成协议」**：`new URL('example.com:8080/path')` 把 `example.com:` 当协议、
   `8080/path` 当路径 → hostname/port 双双为空。`localhost:5173` 是本地调试最常见写法。
   修法：`looksLikeHostPort()`（冒号前含 `.` 或冒号后直接跟数字 ⇒ 是 host:port），补 `http://` 再解析。
2. **协议相对写法 `//host/path`** 被补成 `http:////host/path` → 只补协议名。
3. **`buildUrl({protocol:'https://'})`** 拼出 `https://://a.com` → 归一化 `replace(/[:\/]+$/,'')`。
4. **`FileSize` 切进制单位不跟走**：`unitFactor` 查不到就返回 1 ⇒ **1.5 TiB = 1.5 字节**（差 1024⁴ 倍），
   且 `<select>` 显示项与实际算法单位对不上。修法：抽出 `src/lib/byteUnits.ts`（两表按下标对齐）+
   `toMatchingBase()` 带单位走 + `toBytesText` 内部再归一（**API 边界自愈**）。
5. **JSON→TS 接口名复用只看键名**：`{item:{a:1}}` 与 `{wrap:{item:{a:'s'}}}` 第二处**静默复用** `a: number`
   —— 生成的类型与数据打架。修法：签名加入 `kindOf(values)`（粗粒度类型标签），不同结构才复用；
   顺带把序号递归改成 `while` 找空位（旧版第三次冲突会产出 `Item22`）。
6. **`parseJsonPath` 把不支持的语法当字段名**（`[?(@.price<10)]`、`[0:2]`）→ 安静返回 0 命中，

  往量高壳里垫一块等高透明占位（spacer）→ 壳变高 → `bar_set_height` 窗口跟着长高把面板包进来；
  面板收起占位即撤、窗口缩回。参照物必须是**卡片**（cardRef）而非量高壳——壳的高度里已含占位，
  拿壳当参照会「垫高→超出为0→撤占位→又垫高」自激抖动。展开态下卡片比面板高，超出量为 0，自然不垫。
- **装机**：build-release.sh 6 分钟 EXIT=0（nsis 5 MB / handy.exe 11 MB，exe 15:58 晚于 dist 15:53）。
  装机踩坑一次：第一次 Start-Process 的安装器路径写成了**安装目录**下的旧副本（exe 还是 15:42 旧版），

## V33（~22:40–）模型推倒重来：格子 = 真实收纳目录 + 挂件容器

### 1. 三条根因（全是设计层面的，不是小 bug）

| 现象 | 真根因 |
| --- | --- |
| 「复制了一份」 | V30 的 `grid_desktop_sync` **自动收录**把桌面文件登记成**引用**，文件本体仍在桌面根 → 桌面与格子各一份。用户看到的就是复制 |

### 5. 自查抓到并修掉的真缺陷：便签「每敲一个字落一次库」

「卸载时落一次」的 effect 写成了 `useEffect(() => () => flush(draft), [flush, draft])` ——
`draft` 在依赖里 ⇒ **每敲一个字都会重挂 effect**，上一次的 cleanup 就在当前这一笔上跑一次 flush：
① 每个字符打一次 IPC + 写一次 SQLite（防抖等于没有）；② 顺手把刚设好的防抖定时器清掉，
导致「打完停手」那一笔反而要等失焦/卸载才落盘（webview 被强杀就丢字）。
**修法**：加 `draftRef` / `onSaveRef` 两个镜像 ref，`flush` 依赖降到 `[boxId]`，
卸载 effect 只依赖 `flush` → 只在真正卸载时落一次。**教训：把频繁变化的值放进 effect 依赖，
必须反问「这个 effect 的 cleanup 会不会在每次变化时都跑一遍有副作用的动作」。**

## V34 批次（09-16 23:49 → 09-17 00:20，跨零点；规则：以 `Get-Date` 为准，本批因叙事连续仍记在 09-16）

**用户反馈**：4 张截图 + 12 条。核心是三条「系统性」抱怨 + 若干具体缺陷：

### 1. ★ 最有价值的一条：「格子跑到我其他窗口上面」＋「点别处就消失」是**同一根因**

用户把它说成两个现象（一条嫌它盖住窗口，一条嫌它一点就没了），实际是一条因果链：

> `show_overlay()` 里先 `apply_attach()` 把窗口按基准层插到「桌面正上方」，**再** `show()` ——
> 而 `show()` 会把窗口提拔到 **Z 序顶层**，刚贴好的层级当场被顶掉。

- 顶上去了 ⇒ 用户看到「跑到其他窗口上面」；
- 它虽在顶层却**不是激活窗口**（`make_unfocusable` 不抢焦点）⇒ 用户点任意别的窗口，
  那个窗口被激活盖过来 ⇒ 用户看到「点别处就消失了」。

**修法**：两处 `show_overlay` 分支一律 **`show()` 在前、`apply_attach()` 在后**。
**方法论**：同一个模块两条相反的抱怨，先怀疑它们是同一个机制的两端，别当成两个 bug 分别改。

### 2. 驻留语义：格子层「该在就在」

用户原话「除非 handy 主程序退出，他才跟着退出」= 长期驻留。旧轮询线程碰到「窗口不在」一律 `break`
退出线程 ⇒ 一次意外之后就永久不管了。改为区分：用户主动收起（`overlay_visible=0`）→ 正常退出；
状态仍是显示中 → **自动重建**（`RESURRECT_COOLDOWN_SECS=30` 冷却 + `missing_ticks % 500` 降到约 30 秒判定一次）。
`REASSERT_TICKS` 250 → **40**（约 2.4 秒），保留「连续两次判定才动手」去抖 —— 直接回应
「某些情况才能永久驻留」：真正的错位现在 5 秒内必纠正。

### 3. 本轮「整类被跳过」型缺陷（值得记住的模式）

### 4. 日历挂件对齐工作台的正确姿势：**复用纯函数，不复制 UI**

先读了 `workstation/CalendarPanel.tsx`，发现它把可复用部分都抽在 `src/lib/lunar.ts`、
`src/lib/holidays.ts`、`planUtils.buildMonthGrid/isSameDay` 里 ⇒ 桌面挂件直接调同一批函数，
于是**农历/节气/节日/休班/干支天然逐项一致**，不存在「两处实现漂移」。
数据同样复用 `todos` 表（`detail` 承载描述）⇒ 桌面勾完工作台同步，不需要新表、也没有第二份真相。

### 5. windows-rs 0.58 三个签名坑（改图标这条路踩的）

1. `IImageList` 在 `Win32::UI::Controls`，**必须额外开 `Win32_UI_Controls` feature**（否则 E0432）。
2. `SHGetImageList(size)` 被包成**泛型返回** `Result<T>` —— **一个参数**，不再手写 IID
   （旧写法 `SHGetImageList(size, &IID_IImageList, &mut ptr)` 直接 E0061）。
3. `IImageList::GetIcon(i, flags) -> Result<HICON>` 是**返回值式**签名（老版本是 `&mut HICON` 出参）；
   `flags` 要**裸 `u32`** ⇒ 写 `ILD_TRANSPARENT.0`。
另外 `SHGFI_*` 组合要包 `SHGFI_FLAGS(...)`，`DestroyIcon` 在 `Win32::UI::WindowsAndMessaging`。
