## V77 · 桌面日历：每格补主题色描边

**用户原话**：「主要是每个小格子没有边框 上下两个小格子看着穿在一起了」。

**根因**：`CalendarWidget` 的日期格**只有今天/选中才有底色**，其余 30 来个日子是透明底，
格子之间仅靠 `gap-px` 的 **1px** 缝分隔 ⇒ 纵向相邻两格的「上一格农历」与「下一格数字」
只隔 1px，视觉上连成一片。（V76 修的 `mt-auto` 是「点归属不清」，这次是「格子归属不清」，
两个问题同源：都因为格子没有边界。）

**改法**：`CalendarTheme` 新增 `cell` 字段，每格叠一圈 **`ring-1 ring-inset`**：

| 主题 | cell |
|---|---|
| `''` 深色玻璃 | `ring-1 ring-inset ring-white/15` |
| amber/rose/sky/emerald/violet | `ring-1 ring-inset ring-<色>-900/20` |
| slate 素白 | `ring-1 ring-inset ring-slate-900/20` |

应用处：`${isToday ? '' : theme.cell}` —— **今天不叠**，它自带 `ring-sky-400/80`，
两圈 ring 颜色类**同权重**，谁生效取决于 Tailwind 生成顺序，不可靠。

**为什么用 ring 不用 border**：ring 是 box-shadow，**不占布局**。实测格子仍是
**52.8×52.8 正方、行距不变**（`getComputedStyle` 复核 `boxShadow` 含
`rgba(255,255,255,0.15) 0 0 0 1px inset`）。用 `border` 会挤压内容盒，
跟 V76 刚锁死的几何账（52/53px）过不去。

**验证**（浏览器渲染真组件 + 真机 `handy.db` 的待办经 mock IPC 注入）：
- 裁同一矩形做三方对照：①无边框（糊）②有边框·深色玻璃（清楚）③有边框·素白（清楚）。
  见 `.build-logs/compare-v77.png`，合成脚本 `.build-logs/compose-v77.py`。
- `?demo=calendar` 预览页 → `shot-C-border.png` / `shot-D-noborder.png`（后者是
  DOM 上临时抠掉 `ring-white/15` 拍的「修复前」）/ `shot-E-light.png`。

## ⚠️ 踩坑：同文件多处 `Edit` 并行 = 互相覆盖

7 套主题要各加一行 `cell`，我**并行**发了 7 个 `Edit` → 只有最后落盘的 2 个生效，
`tsc` 报 5 处 `Property 'cell' is missing`。**同文件多处改动必须串行**（这条 MEMORY 里
早有记录，这次又踩了一遍 —— 并行只对**不同文件**安全）。

## ⚠️ 踩坑：模板字符串里的空表达式

想给 `className` 再插一段，写成了

```
... ${isSelected ? a : b} ${ /* 只有注释 */ } ${inMonth ? … }
```

第二个 `${}` 里**只有注释没有表达式** ⇒ `tsc` 报 `TS1109: Expression expected`。
注释要贴在**表达式之后、`}` 之前**，不能自成一段。

## V78 · 日期格内容改垂直居中（上下留白均等）

**用户原话**：「日期数字节日计划 三行文字满了后，上边距和下边距不平衡 我喜欢看上去
上下边距都一样的效果，其他都可以了 不过风格可以跟现有一样，跟随桌面主题」。

**实测数据**（`getBoundingClientRect`，35 格完全一致）：

| | 修复前 | 修复后 |
|---|---|---|
| 格子高 | 52.8px | 52.8px（**没动**） |
| 三行内容高 | 38px（13 数字 + 2 间距 + 10 农历 + 4 间距 + 9 标记） | 同 |
| **上留白** | **2px**（= `py-0.5`） | **7.4px** |
| **下留白** | **12.8px** | **7.4px** |

**根因**：`justify-start` 把内容顶在上边，52.8 − 4(py) − 38 = 10.8px 富余全落在底下。
改 `justify-center` ⇒ 10.8 对半 ⇒ 各 5.4，加回 padding = **上下各 7.4**。

**关键前提（别漏）**：能用居中是因为**三行都是定高**。原先农历行只有
`text-[10px] leading-none`，`badge` 为空时会塌成 0 高 ⇒ 内容高变成 28 ⇒ 居中的话
**那一格的数字会比邻格低一截**。所以同时给农历行补了 `h-[10px]`，把内容高锁死在 38。
（标记行本来就有 `h-[9px]`；数字行恒非空、13px。）

**验证**：`.build-logs/compare-v78.png`（①顶到上面 ②上下居中，同视口同数据），
量留白的探针 `.build-logs/probe-margins.js`（**可复用**：改任何日期格间距后跑一遍，
直接读「上留白/下留白/内容高」三列，不用肉眼）。

**风格未动**：外壳、主题、字号、描边全按 V77，用户明确说「其他都可以了」。

**收尾**：`tsc` 0；回归 **21/21**；exe（08:52:19）晚于 dist（08:42:29）；装机前非接管态
（无进程、`grid_meta` 三键皆 0）⇒ 直接 NSIS `/S`，exit 0，mtime 01:12:44 → **08:52:08** ✓；
`cmp -l` 新构建 vs 已装 = **3 字节**（装机生效）；未启动 GUI。

## ★ `cmp -l` 的正确用法（推翻 09-24 那条错误结论）

09-24 我在**装机之前**拿新构建 exe 去比**旧安装** exe，读到 2,697,751 字节差异，
于是写下「3 字节只适用于只改版本号」—— **错的**。那个差异只是「新 vs 旧」的正常结果。

**正确做法**：`cmp -l` 取证**必须在装机之后**做，比的是
`src-tauri/target/release/handy.exe` ↔ `%LOCALAPPDATA%\Handy\handy.exe`：

| 读数 | 含义 |
|---|---|
| **3 字节** | ✅ 装机生效 —— 装的**就是**刚构建的这个二进制（NSIS 只改了 3 字节的版本标记） |
| 大量差异 | ❌ 装的是**旧**构建 / 装机根本没生效（不是"前端打进去了所以正常"） |

`MEMORY.md` §5 里那句「只应差 3 字节」**本来就是对的**，是 09-24 的我误用了它。
本次复核：两边**同为 11,302,912 字节**，`cmp -l` 差 **3**。

# 2026-09-25 上午 V79：「打开 Handy 后格子还摊着 / 退出整理收不起来」

**用户原话**：「每次我新打开 handy 后是这样，整理过的图标还在展示，重新点击整理就好了；
退出桌面整理也是格子一直都在桌面就像图片中这样，整理没有退出等」（附图，**图里任务栏时钟是 11:17**
= 启动那一刻）。

## 取证（先拿证据再动手）

1. `handy.log` 11:17:23 启动，**同一秒**先打「显示桌面工具栏（格子内容收起，原生图标恢复）」
   又打「显示挂件层（复用/新建窗口）」⇒ 两条路都跑了。
2. 读进程命令行（`wmic` 已不可用、PowerShell 工具整段无输出 ⇒ 写 `.build-logs/read-cmdline.py`，
   走 `NtQueryInformationProcess` → PEB+0x20 → `RTL_USER_PROCESS_PARAMETERS`+0x70）：
   **`handy.exe --show-grid`** ⇒ 用户是从**桌面右键菜单「打开 Handy 桌面整理」**进来的（by design）。
3. `handy.log` 11:19:25 / 11:20:39 / 11:20:47 / 11:20:57 **连打四条「收起挂件层」** —— 库改了四次，
   界面纹丝不动 ⇒ 用户连点四次「退出」。
4. **11:17 启动那一刻 `desktop_takeover=0`** —— 因为 09-25 01:12 那次装机把三键**全**置了 0。

## 两个根因（一个是我的）

**D1 · 广播只挂在一条路上 ⇒「退出整理」收不起来。**
前端 `contentHidden` 只有两个来源：挂载时查 `grid_overlay_status`，以及 `grid:visibility` 事件；
而 V48–V78 期间**只有 `tray.rs` 会发**这个事件。于是桌面右键菜单「退出桌面整理」（`--hide-grid`
→ `hide_overlay_now`）与轮询线程自动重建（`show_overlay`）全都**只改库、不改界面**。
这就是「日志打了收起、格子一直在」。属 V61「一个可变状态只许一个记账人」同一族。

**D2 · 装机把用户偏好一起清零（我的错）。**
`desktop_icons_hidden` 是**事实**（我们刚亮了图标 ⇒ 必须归零）；但
`desktop_takeover`（**用户偏好**）与 `overlay_visible`（**用户上次的显隐意图**）一律清零 =
**悄悄替用户关掉接管** ⇒ 11:17 用 `--show-grid` 显示整理层时 `apply_takeover_pref` 看到偏好为关、
**不藏原生图标** ⇒ 用户看到「格子 + 整理过的原生图标」两份内容 ⇒ 点一次「整理」把偏好写回 1
才正常 —— 正好是那句「重新点击整理就好了」。

## 改法

- `commands/grid.rs` 新增 `emit_visibility(app, visible)`；`show_overlay`(true)、
  `show_launcher_only`(false)、`hide_overlay_now`(false) 三处**写完真源立刻广播**。
- `tray.rs` 删掉自己那份广播（重复且制造第二个记账人）。
- `GridOverlay.tsx`：`contentHidden` 初值 `false` → **`true`（fail-closed）**，并把
  **监听注册提到状态查询之前**（否则查询在途时的那次广播会丢）。
  代价只是一帧延迟；初值 false 的代价是**冷启动必然先摊开一屏格子**，且查询失败就永远停在摊开态。

## 守卫（不变量必须落成守卫 + 变异）

`test-drag-pointer.mjs` 新增 **⑮** 段 6 条：三处写入都紧跟广播、`grid:visibility` 全 Rust 侧只此一处、
托盘不再自己发、初值必须 `useState(true)`、监听必须在查询之前。
`guard-mutation-check.py` 新增 4 条破坏用例（**变异 43→47**）——
⚠️ 踩坑：第一版插错了列表（插进 `test-desktop-constants` 那组），4 条全部「仍是绿」，
搬到 `test-drag-pointer` 组后才全部「变红 ✓」。**变异用例必须挂在对的守卫文件下**。

## 验证与装机

- `tsc` 0；`cargo check --release` 无警告；回归 **21/21**；变异 **47/47 全部被捕获**；
  `test-drag-pointer` 基线 117 PASS。

# 2026-09-25 下午 V80：日历要能选年 + 能加生日 / 特殊日期

**用户原话**：「日历上不能选年呢？例如我想回到1988年我生日那天记录下我的生日
或者我记录别人的生日等 或者特殊日期现在怎么没有添加了。」

## 取证（两条都是**能力缺失**，不是样式问题）

| 诉求 | 现状 |
|---|---|
| 选年 | `CalendarWidget` 只有 ±1 月箭头 ⇒ 2026 → 1988 = **456 次点击**，功能上等于没有 |
| 加纪念日 | 挂件**只读** `settings.anniversaries` 画蛋糕标记；能增删的地方在**工作台** `CalendarPanel`（V63 后主窗口已退场）⇒ 用户根本找不到入口 |

## 改法（`src/modules/desktop-grid/DesktopWidgets.tsx` + `src/lib/lunar.ts`）

1. **标题变按钮** → 年月快选面板：年份输入框（受控 `yearDraft`，回车 / 失焦生效）+ `« ‹ › »`
   （±10 / ±1 年）+ 12 月宫格；左右箭头**按住 Shift 点 = 翻年**。
2. **`jumpTo(y, m)` 作为唯一跳转入口**，做三件事：
   - **年份先夹进 `LUNAR_MIN_YEAR..LUNAR_MAX_YEAR`**（新从 `lunar.ts` 导出，年表只有
     1900–2100）。不夹 ⇒ `LUNAR_INFO[year-1900]` 取到 `undefined`，**农历整列空白、
     不报错不崩溃** —— 最难查的那类坏法；
   - **带着 `selected` 一起走**（`defaultSelectedOf`：当月=今天，其他月=1 号）。
     否则月份翻到 1988 年 6 月、下面「……的计划」与输入框还停在出发月 ⇒
     用户以为在给 1988 年加生日，实际加到了今天。
   取 1 号而不是「保持原日号」：`new Date(y, m, 31)` 会**静默滚到下个月**，比显式取 1 号更骗人。
3. **礼物按钮 → 纪念日面板**：名称 + 日期（留空 = 选中那天）+ 类型 + 每年重复 → 增删；
   写盘走 **`patchSettings`（read-modify-write）**，**不许** `writeSettings`（整份覆盖会
   把 Rust 侧刚写的 `modules` 冲掉，`store.ts` 里明写着这条）；点条目 `gotoAnniversary` 跳到那天。
4. 两块面板**互斥**（400px 挂件装不下叠着开），且展开态必须进 **`onContentHeight` 依赖**
   —— 否则盒高按旧值算，计划区被顶出可视区。
