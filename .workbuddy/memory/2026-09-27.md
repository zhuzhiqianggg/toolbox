# 2026-09-27

## V81 桌面右键：菜单期间「把桌面暂时还给系统」

用户两条反馈（原话见 CONVENTIONS §32）：① 桌面右键新建文件夹很慢、也不能「点两下重命名」；
② 创建的文本文件 / 文件夹「完全没有生效，刷新页面什么都没干」。

### 取证：先分清「弹的是谁的菜单」（这步差点走错）

- 桌面空白右键**本就穿透**到系统桌面（根画布 `pointer-events:none` + Rust 整窗穿透），
  弹的是 **Explorer 真原生菜单**，Handy 子菜单由注册表 `DesktopBackground\Shell` 注入——
  也就是说「默认右键行为」本来就没被我们改。
- ⚠️ `handy.log` 里几百条 `原生右键菜单失败（::{00021400-…}\Desktop）：拿不到 shell 对象`
  是**另一条路**（`GridOverlay` 里兜底的 `shellContextMenu`）的失败记录，与用户看到的菜单无关；
  那个 CLSID 写法**从来没成功过**。差点据此判断成「菜单是我们复刻的」而走错方向。
- 真根因：**接管态把 `SysListView32` `SW_HIDE` 了**。原生「新建文件夹」的四步里，
  目录真建了、item 真插了、原位改名编辑框真开了——**全在那个隐藏视图里**。
  用户看到的只能是「什么都没发生」。「慢」同理。

### 改动

- 新增 `src-tauri/src/platform/desktop_handoff.rs`：`SetWinEventHook` 旁听
  `MENUPOPUPSTART/END`；借出 = 显示 listview + 隐藏挂件窗；收回前**等 `label_editing()` 结束**
  （原生新建是菜单关闭**之后**才进改名的）+ **复核 `icons_taken()`**（菜单里有「退出桌面整理」，
  点了就不能再藏）；超时 120s；收回后 emit `grid:desktop-changed`。
- 纪律：**一个字节都不改鼠标路由**。拦截再转发、或为让菜单看见结果去动 `ignore_cursor_events`，
  都会把「默认右键行为」变成我们自己实现的东西——那正是用户从 V43 起反对的。只做旁听。
- `grid.rs`：`desktop_icon_view` → `pub(crate)`；新增 `icons_taken()` / `handoff_active()`；
  `reassert_takeover` 与「窗口不可见」自愈**在借出期让路**（不让路 = 100ms 内被抢回来，等于没修）；
  `show_overlay` 里 `ensure_watcher`。
- `GridOverlay.tsx`：监听 `grid:desktop-changed` → `syncDesktop()` 重扫；桌面空白右键删掉那条
  必然失败的复刻菜单调用（直接弹 Handy 菜单，表现与它失败时一致，只是不再白等）。
- `Cargo.toml` 加 `Win32_UI_Accessibility`。

### 踩坑

- `EVENT_SYSTEM_MENUPOPUPSTART/END`、`WINEVENT_OUTOFCONTEXT/SKIPOWNPROCESS` 在
  `windows::Win32::UI::WindowsAndMessaging`，**不在** `Accessibility`（后者只有 hook 函数）。
- `FindWindowW` / `FindWindowExW` 在 windows-0.58 返回 `Result<HWND>`，不能取 `.0`。
- `app.get_webview_window()` 需要 `use tauri::Manager`。
- Bash 命令里出现 `PowerShell` 字样会被安全策略整条拦下 → 含该词的脚本改用 Write 写文件再跑。

### 待用户拍板
