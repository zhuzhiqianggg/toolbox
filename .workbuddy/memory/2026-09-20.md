## 做了什么

### 1. 入口改格子样式（`GridOverlay.tsx`）

- 抽 `BOX_SHELL_CLASS`：**收纳格与快捷入口共用同一套边框/阴影/磨砂** —— 用户要的「格子样式」
  就是「和收纳格长得一模一样」，两处类名一旦分叉就会退回「飘在桌角的小面板」。
- `fixed right-8 bottom-8`（32px = 引擎 `ARRANGE_MARGIN`），宽 `DOCK_W = CALENDAR_NATURAL_W = 320`，
  高上限 `DOCK_MAX_H = 320`（超出在格内滚动，`DOCK_BODY_MAX_H` 由常量推出而不是另写 282）。
- 同款标题栏（`h-9` + 渐变 + 下边框）+ 名「快捷入口」+ 设置/折叠两按钮；内容区
  `grid grid-cols-3 gap-1` 分三块（应用入口 / 系统入口 / 我的快捷方式）。
- 新增 `DockCell`（图标块 + 11px 标签，克制观感，不带霓虹发光/放大）。
- 折叠态 `localStorage`（`handy:grid.dock-collapsed`）持久化。
- z 值随右侧面板开关切 `z-[100]` / `z-30`（面板铺满档时退到面板之下）。
- 保留原有拖放收藏逻辑；右键移除系统入口时落 `quickActionsCustomized: true`。
- 文案「快捷条」→「快捷入口」；`FileIcon size` 16 → 22。
- 日历盒子内容区加 `overflow-y-auto grid-scroll`（被压矮时仍看得全）。

### 2. 引擎加「入口禁区」（`src-tauri/src/commands/grid.rs`）—— 本轮唯一结构性改动

原先前端那块矩形对引擎是「不存在的东西」。新增：

- `const DOCK_BOX_W = CALENDAR_BOX_W`（=320）、`const DOCK_BOX_H = 320`；
- `fn dock_rect(work_w, work_h)` —— 右沿 = 挂件带右沿，下沿 = 工作区下沿；
- `fn column_bottom(x, w, work_h, reserved)` —— **只看横向区间相交**（与 `needs_placement` 判据⑤
  同一套口径），压上禁区就把这一列下沿收到 `r.y − ARRANGE_GAP_Y`，否则 `work_h − ARRANGE_MARGIN`；
- `stack_in_column` / `pack_overflow` 的 `work_h` 参数**改名 `bottom`**（语义从「工作区高」变成
  「这一列的绝对下沿」），`place_widget_columns(..., &reserved)` 两条分支都改用 `column_bottom`；
- `layout_all_boxes_with` 里构造 `let dock = dock_rect(...); let reserved = [dock];`。

### 3. 入口口径重策展

`src/core/settings.ts`：

- `DEFAULT_QUICK_ACTION_IDS`（新 9 项）＝ `powershell-admin` · `cmd-admin` · `dns-flush` ·
  `hosts-edit` · `env-vars` · `ncpa` · `services` · `proxy-settings` · `temp-folder`

  否则用当前默认；

`src/core/types.ts` 加 `quickActionsCustomized: boolean`；`src/lib/store.ts` 的 `withDefaults()`

## 踩到的坑

1. **`test-desktop-constants.mjs` 建好了但没登记进 `run.mjs`** —— 跑全量回归显示 18/18「全绿」，
   其实是新套件压根没跑（`grep "===== "` 才看出来）。**教训：新建回归后必须确认它出现在总入口的输出里**，

2. **`DOCK_BODY_MAX_H` 初版写 `DOCK_MAX_H - 38`** → 常量解析器读不出来（拿不到数字）。

   （同 §26 教训：解析不了要**响亮失败**，不能静默跳过。）

# V57 批次（同日夜）— 「格子拖不动，只能靠整理」

> 用户原话（23:53）：「现在就剩一个问题，现在桌面上的是不能自己拖动调整的，只能通过整理自动整理
> 后面用户不能自己新建格子然后手动拖动整理」

## 真机取证

- `db-probe.py`：11 个格子，**除 `便签 6` 外全部 `manual = 1`**，但坐标**全部恰好落在列网格上**
  （收纳 341/706、便签 1071、日历 1355）⇒ 用户反复试过，**没有一个手工位置被留住**。
- 日志 23:51–23:55（用户启动 V56 后 4 分钟内连点「一键整理」三次）：
  ```
  23:54:44  收纳区空间不足，被顶出屏幕的格子：新格子 14     ← 幽灵格子
  23:55:20  整理布局（增量补齐）：… 手工保留 5 个            ← 一分钟前还是 8 个
  23:55:38  整理布局（增量补齐）：… 挪动 1 个
  ```

## 五条根因

| # | 根因 |
| --- | --- |
| ① | **`setEditMode(true)` 是空操作**（V52 兼容壳，传 true 只 `return new Set(prev)`）—— 而「新建格子」正是调它。`addBox` 的提示却写着「**已解锁**，可以直接拖动/拉大小/改名」 |
| ② | **`toggleEditMode` 的解锁分支也是 `new Set()`** ⇒ 只能锁不能解；且 **`grep` 全仓只有定义处、从未接到任何 UI** ⇒ 桌面上根本没有全局解锁这条路 |
| ③ | **箱体拖动被 `if (!editMode) return;` 卡住** ⇒ 锁着的格子只有 36px 标题栏能拖，抓箱体空白处毫无反应（用户的本能动作） |
| ④ | **V50「挂件一律由列规则安置，不看 `manual`」** ⇒ 拖便签/日历永远在下一次布局被弹回固定位置 |
| ⑤ | **没有越界兜底** ⇒ 「新格子 14」停在 `y > work_h`，看不见够不着又没删掉 = 幽灵 |

①②③ 叠加 = 用户那句话本身。

## 改动

**前端 `GridOverlay.tsx`**

1. 删假接口 `setEditMode` → 三个名副其实的 `unlockAllBoxes()` / `lockAllBoxes()` / `unlockBox(id)`
   （定义位置必须晚于 `boxesRef`）。
2. `focusNewBox` 改调 `unlockBox(boxId)` ⇒ 新建收纳格**立刻可拖/可拉/有操作按钮**（恢复 V38 原意）。
3. `addWidget`（便签/日历）也调 `focusNewBox` —— 之前只有收纳格走这条路。
4. `toggleEditMode` 改为读当前解锁集合：有解锁的 → 全锁；没有 → **全解锁**（真的解开）。
5. **格子右键菜单新增「自由摆放（解锁全部格子）」/「锁定全部格子」**（这是 `toggleEditMode`
   唯一的 UI 入口 —— 它在标题栏右键菜单里，用户 V41 指定的「格子操作唯一入口」）。
6. `<section onMouseDown>` **删掉 `if (!editMode) return;`** ⇒ 移动任何时候都能用；
   锁只收放编辑类能力。
7. `startMove` 加 `stopPropagation()`（标题栏与箱体两个 handler 会冒泡到同一处，避免起两次拖）。
8. `onUp` 加「**没真的动过就不落库**」—— 拖动放宽到任意位置后，单击也会走完 onUp，
   若无条件落库就会把格子误标成 `manual`，点几下全桌都变 manual、整理失效。

**引擎 `grid.rs`**

9. 挂件单列分支**尊重 `manual` 的纵向位置**（落点合法就照它摆，否则退回规则位）；
   **横向仍归列规则**（用户 V50 自己要的「便签一个独立的列」）。`Full` 模式加载前已清 `manual`，
   所以「重新重置整理」自然回到默认纵向顺序。
10. 布局收尾新增**「绝不把格子留在屏幕外 / 压在入口上」**兜底：只动越界者，夹回可见区；
    若落在右下角快捷入口禁区上再抬到它上面。
