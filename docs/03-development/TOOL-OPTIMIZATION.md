## 1. 结论摘要

**一句话**：23 个工具的**功能**早就够用，真正的短板是**「第一次打开时的引导」**和**「离开再回来时的状态」**——
本轮把这两件事做成了**框架级能力**，而不是逐个工具打补丁。

三条主要结论：

1. **共性问题只有两个，且都能一次修好。** ① 空输入框 + 零示例 = 用户不知道能喂什么；② 切走再切回，输入全丢。
   针对 ① 新增 `SampleBar` + `CommandShell.samples`；针对 ② 已有 `useToolState`。
   **基建做完，剩下的是接线工作，不是设计工作**——这是本轮最大的杠杆。
2. **三个「主力工具」需要重做而不是补丁。** Cron 解析（只翻译不校验）、正则测试（只有裸输入框）、
   文本对比（两个独立滚动容器导致错位）——三者都是「用过一次就不想再用第二次」的形态，已全部重写。
3. **顺手挖出 5 个真实缺陷**（假按钮、状态被覆盖、冷启动空表、类型错乱、切换重置），
   全部与「功能看起来有、其实没生效」有关，比缺功能更伤信任，已修。

**本轮量化**：重写 3 个工具 · 新增 11 个工具的示例条 · 修复 5 个缺陷 · 新增 3 个横向基建组件。

## 2. 评估口径

每个工具按 **5 个维度**打分（1 差 → 5 好），成熟度取加权印象分：

| 维度 | 追问 | 权重 |
| --- | --- | --- |
| **A 冷启动可懂** | 第一次打开、不看文档，10 秒内知道该干什么吗？ | 25% |
| **B 输入效率** | 要敲多少下？有示例、有粘贴、有联动吗？ | 20% |
| **C 结果可用** | 能否一键复制 / 导出 / 继续喂给别的工具？ | 25% |
| **D 边界容错** | 空输入 / 非法输入 / 超大输入 / 特殊字符——会崩还是会解释？ | 15% |
| **E 一致性** | 状态是否保留？交互是否与其它工具同构？ | 15% |

> 打分依据：源码实测（`tsc`/`build` 通过）+ 结构审查 + 示例条与持久化接入的静态核查（`grep`）。
> 未实机跑 GUI 的部分（文件选择、下载落盘）标注为「待装机验收」，不虚报为已验证。

## 4. 本轮落地的横向基建（一次投入，全工具受益）

### 4.1 `SampleBar` + `CommandShell.samples`（新增）

**问题**：23 个工具里，绝大多数打开后只有一个空输入框加一行占位文案。占位文案（`placeholder`）只能提示
「格式」，不能演示「价值」——用户还是得自己编数据。

**方案**：把示例做成**外壳的一等公民**。

```tsx
<CommandShell
  samples={[
    { label: '日志刷屏去重', description: '同一错误重复打印，保留首次出现', apply: () => setInput(LOG) },
    { label: '大小写混合主机名', description: '配合「忽略大小写」即合并', apply: () => { setInput(HOSTS); setIgnoreCase(true); } },
  ]}
>
```

设计要点（这三条决定了它能不能被 23 个工具复用）：

- **`apply` 是调用方闭包**：可以只填输入框，也可以「填 + 开开关 + 切页签」——文本对比那类需要同时设置
  左右两栏、或 `CsvJson` 需要跟随页签换一组示例的工具，都能覆盖；
- **示例条挂在外壳、内容区之上且 `shrink-0`**：`fill` 模式（编辑器类工具）内容区是 `flex-1` 撑满，
  示例条必须是它的兄弟节点，否则会把输入框挤出可视区；
- **不写空数组**：`samples` 省略或无内容时不渲染，不占一条空白横线。

### 4.2 `useToolState`（V20 早前已建，本轮扩大接线）

localStorage 持久化，防抖 400ms、卸载 flush、256KB 上限、超限静默放弃。
**当前已接线 3 个**：`cron-descriptor`、`regex-tester`、`text-diff`（正是最费输入的三个）。
其余 20 个待接线（P1）——**接线成本约 3 行/工具，属于机械劳动，不宜再拖**。

### 4.3 复用件清单（新工具应默认使用，不要再各写各的）

| 组件 | 用途 | 落地情况 |
| --- | --- | --- |
| `SampleBar` / `CommandShell.samples` | 可点击示例 | 11 / 23 |
| `useToolState` | 工具状态持久化 | 3 / 23 |
| `CodeBlock`（零依赖语法高亮） | 结果区带高亮 | 便签 / Markdown 渲染已用 |

## 5. 五个真实缺陷（比缺功能更伤信任）

| # | 工具 | 症状 | 根因 | 修法 |
| --- | --- | --- | --- | --- |
| 1 | `csv-json` | 「复制结果提示」按钮既不下载也不复制，只弹一句 toast | 占位实现忘记替换 | 改为真正的导出 `.json`/`.csv` 文件 |
| 2 | `relative-time` | 「复制描述」按钮只弹「暂无可复制内容」 | 同上 | 改为「填入当前时间戳」，验证「刚刚」边界 |
| 3 | `unit-converter` | 切类别时把用户已选的**源单位**强制重置为第一个 | `useEffect([categoryId])` 无条件 `setFromUnit(units[0])` | 新类别里仍存在就保留，否则才回退 |
| 4 | `unit-converter` | `CATEGORIES[categoryId] ?? CATEGORIES.length` —— 回退值是 **number** 而不是 Category | 手滑写成 `.length` | 去掉错误回退，类型归位 |
| 5 | `uuid-generator` | 示例按钮「先 setState 再调 generate」会读到**旧值**（经典闭包竞态）；打开是空表 | `generate` 依赖 state，示例无法传参 | 抽出 `generateWith(n, upper, dash)`；`useState` 惰性初始化实现冷启动预生成 |

> 这一类的共同特征：**界面上有入口，实际不生效或反向生效**。用户不会报「按钮是假的」，
> 只会得出「这工具不太靠谱」的结论。建议把「交互元素的副作用是否真实发生」纳入 QA 检查项。

## 6. 分工具优化方案

### P0 —— 本轮已完成

#### 6.1 Cron 解析（`cron-descriptor`）· 重写

| 项 | 内容 |
| --- | --- |
| 现状 | 5 段拆开翻成一句话；不校验、不推算、不支持 Quartz 扩展 |
| 问题 | 用户真正要的是「**下次什么时候跑**」和「**我这条写得对不对**」，翻译一句话只是副产品 |
| 方案 | 自研纯函数引擎 `src/lib/cron.ts`：`analyzeCron` / `nextRuns` / `buildCron`；支持 5/6/7 段、Quartz `L W #`、`?`、`@daily` 类宏；逐字段校验并给出人话解释；推算未来 8 次执行；`CRON_PRESETS` 20 条按场景分组；反查生成器（说出需求 → 给出表达式） |
| 结果 | 从「翻译器」变成「校验器 + 推算器 + 生成器」 |

#### 6.2 正则测试（`regex-tester`）· 重写

| 项 | 内容 |
| --- | --- |
| 现状 | 一个正则输入框 + 一个文本输入框 + 匹配结果 |
| 问题 | 不知道写什么正则；不知道自己的正则错在哪；测试文本太干净，跑不出真实场景 |
| 方案 | 新增 `src/lib/regexLibrary.ts`：**30 条**带说明/样本/用例的内置正则（常见校验 / 网络与运维 / 日志分析 / 文本处理 / 进阶陷阱 五组）；**9 套真实多行样本**（Nginx、应用日志、慢查询、syslog、K8s YAML、JSON、脏数据、Markdown、Shell）；`explainPattern` 逐 token 讲人话；四页签：匹配明细（含命名组表）/ 替换预览 / 语法解释 / 用例验证 |
| 结果 | 从「测我写的正则」变成「教我怎么写 + 帮我验证」 |

#### 6.3 文本对比（`text-diff`）· 重写

| 项 | 内容 |
| --- | --- |
| 现状 | 左右两个独立滚动容器，各自滚；相同行不对齐；切走回来全丢 |
| 问题 | 用户原话：「**左右没有跟随基准行滚动**」「空行和需要虚拟展示空缺，但要保证相同的行跟随整体对齐」 |
| 方案 | **单一滚动容器 + CSS Grid 两列** —— 行对行天然对齐、滚动天然同步，不需要写一行同步 JS；`line === null` 渲染成**虚线占位块**（虚拟空行）；`buildRenderItems` 折叠连续未变更区块（上下各留 3 行上下文）；并排 / 行内两种视图；`useToolState` 持久化 |
| 结果 | 对齐与同步由**布局**保证，而不是靠事件监听硬凑——不会再有「滚着滚着错位半行」 |

### P1 —— 建议 V21 完成（机械接线，风险低）

把统一示例条 + 状态持久化铺到剩余 **8 个**工具：
`timestamp` · `json-formatter` · `base64-codec` · `url-codec` · `jwt-decoder` ·
`password-generator` · `hash-generator` · `qrcode-generator`

每个工具的示例建议（专家视角，直接可落）：

| 工具 | 建议示例 |
| --- | --- |
| `timestamp` | 现在 / 昨天此刻 / 一年前（检验「年」档） / 毫秒 13 位（运维日志两种都常见） |
| `json-formatter` | 压缩成一行的 API 响应 / 中文与 emoji（校验 UTF-8 处理） / 尾部多余逗号（检验报错定位） |
| `base64-codec` | 中文文本 / `{"a":1}` / 二进制片段（检验 UTF-8 安全） |
| `url-codec` | 带中文查询串的完整 URL / 双重编码（`%25`） / 表单 `+` 空格语义差异 |
| `jwt-decoder` | 标准 HS256 示例 token / 单段结构（说明它不校验签名） / 过期 token（突出 exp 展示价值） |
| `password-generator` | 16 位强密码 / 32 位长口令 / 纯数字（说明强度下限） |
| `hash-generator` | 短文本 `hello` 对照公开向量 / 大文本 / 与已知 MD5 比对（校验一致性） |
| `qrcode-generator` | `https://` 链接 / WiFi 配网串（`WIFI:T:WPA;S:...`） / vCard 名片 / 长文本（触发容量告警） |

### P2 —— 中期方向

| 方向 | 价值 | 说明 |
| --- | --- | --- |
| 工具间管道 | 高 | 「哈希 → 对比」「JSON → TS → 编辑器」，减少跨工具复制粘贴 |
| 输入历史 / 最近使用 | 中 | 每个工具保留最近 N 条输入，配合已有「最近使用」排序 |
| `unit-converter` 扩类 | 中 | 面积 / 体积 / 压力 / 网速（`Mbps ⇄ MB/s` 是运维高频换算，当前完全缺失） |
| `sql-formatter` 完整解析 | 中 | 当前是启发式替换，不处理字符串字面量与注释内的关键字 |
| `cron` 时区支持 | 低 | 展示「服务器时区 UTC 下，本地看到的是几点」 |

## 7. 明确不做的取舍

| 事项 | 决定 | 理由 |
| --- | --- | --- |
| 引入 `sql-formatter` / `cron-parser` 等成熟库 | 暂不引入 | 项目当前**零新增依赖**是优势；现有启发式实现已覆盖 90% 日常场景，用新增包换取边际收益不划算。若 P2 要做完整 SQL 解析，再重新评估 |
| 全工具统一 `useToolState` | 分批 | 一次性改 23 个文件会把回归面放大到不可控；先接线最费输入的三个，其余按 P1 逐批 |
| 云端同步 / 账号 | 不做 | 本地优先是产品边界（PRD 既定），工具状态留在本机 localStorage |
