> **本文解决的问题**：桌面整理上线以来，用户反复报同一类现象 ——
> 「点一下桌面空白处，整理好的桌面整个不见了」「隐藏之后桌面空空的」
> 「必须最小化一个顶层窗口，整理桌面才回来」。
> 这些都不是「某个功能没做」，而是**缺少一份权威的桌面层结构定义与状态机**：
> 窗口显隐、原生图标显隐、内容显隐三件事分别由三条代码路径各自决定，
> 于是任何一处猜错，用户看到的就是「桌面没了」。
> 本文先把**结构**定死，再把**逻辑**定死，实现只是它的投影。

## 1. 桌面布局结构（先结构）

桌面层由**六个区域**组成，几何全部落在**工作区**（`work_w × work_h`，已排除任务栏）内，
外边距统一 `ARRANGE_MARGIN = 32`、区内间距统一 `ARRANGE_GAP = 24`。

```
┌───────────────────────────────────────────────────────────────────────────┐
│ ┌──────────┐ ┌───────────────────────────────────────┐ ┌────────────────┐ │
│ │ ① 不整理  │ │ ② 收纳格区（按内容定尺寸 + 列式填满）   │ │ ③ 挂件区（右上）│ │
│ │   竖条    │ │  ┌────────┐ ┌────────┐              │ │  日历 / 便签   │ │
│ │ 系统图标  │ │  │ 文档   │ │ 压缩包  │   ← 第 0 列   │ │  （可多个便签）│ │
│ │ 快捷方式  │ │  └────────┘ └────────┘      = 最右列  │ └────────────────┘ │
│ │ 未归类项  │ │  ┌────────┐ ┌────────┐              │                    │
│ │           │ │  │ 文件夹  │ │ 其他   │              │                    │
│ │ 左起 32px │ │  └────────┘ └────────┘              │                    │
│ │ 多列竖排  │ │  格子高度按内容自动撑开，超高则内部滚动 │                    │
│ └──────────┘ └───────────────────────────────────────┘                    │
│                                                                            │
│              ┌─────────────────────────────┐         ┌──────────────────┐  │
│              │ ⑤ Dock（底部居中）           │         │ ⑥ 工具栏（右下） │  │
│              │ 用户拖入的快捷方式 + 已钉系统入口│        │ 常驻，永远可点   │  │
│              └─────────────────────────────┘         └──────────────────┘  │
│                                                       ④ 桌面抽屉从右侧滑入  │
└───────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 组件 | 内容 | 是否常驻 |
| --- | --- | --- | --- |
| ① 不整理竖条 | `GridOverlay` 内 `looseStrip` | 系统图标（回收站 / 此电脑…）+ 快捷方式 + 未归类文件；**不生成格子** | 仅 `On` 态 |
| ② 收纳格区 | `GridOverlay` 内盒子 | 收纳格（folder / widget），**只登记引用、绝不移动文件**；几何 = 按内容定尺寸 + 列式填满（§1.1） | 仅 `On` 态 |
| ③ 挂件区 | 盒子 `kind = calendar \| note` | 日历（唯一）/ 便签（可多个） | 仅 `On` 态 |
| ④ 桌面抽屉 | `DesktopSidePanel` | 工具（搜索/浏览→就地打开）、快捷（应用入口/快捷方式/系统入口） | 六态均可开 |
| ⑤ Dock | `GridOverlay` 内 Dock | 用户拖入的快捷方式（与抽屉「我的快捷方式」同源） | 仅 `On` 态 |
| ⑥ 工具栏 | `GridOverlay` 内 toolbar | 工具 / 快捷 / 密码箱 · 编辑 / 整理 · 格子 / 便签 / 日历 · 接管 / 对账 / 隐藏 | **恒常驻** |

### 结构上的两条硬约束

1. **区域之间不重叠**：格子流布区的左界由 `loose_strip_rect(...)` 的右缘决定
   （`FlowPlacer{min_x}`），底部给 Dock / 工具栏留出高度；④ 的定位类见
   `DesktopSidePanel.SIDE_PANEL_SHELL`（右缘避开 ⑥、下缘避开 ⑤）。
2. **几何只来自 Rust**：前端不自己排版，`grid_auto_arrange` 算出几何后写入
   `grid_boxes`，前端只负责画。**挂件区**的镜像流布（「第 0 列 = 最右列」）是视觉约定，
   不要在别处再解释一遍；**收纳格区**不是镜像流布，它**右锚定、从右往左**分列（§1.1，V85）。

### 1.1 收纳格怎么落位（V65–V85 的唯一口径）

**尺寸**、**摆放序**、**列数**三件事各管各的，谁都不许去看「格子现在停在哪」——
看一眼就变成自我引用的反馈环（V64「吸附最近的坑」、V66.1「哨兵甩队尾」都栽在这儿）。

| 环节 | 规则 | 实现 |
| --- | --- | --- |
| 尺寸 | **只看自己的条目数**（面积与内容成正比） | `box_own_size` → `desired_box_width` + `box_height_at` |
| 高度上限 | **本带可用高** `zone_h`（不是写死的数）—— 空间宽裕就长到把所有图标摆完 | `content_plan_in` → `box_height_at` |
| 摆放序 | `(面积, 内容量, 高, 宽)` **降序**；完全并列时维持登记顺序 | `size_rank` / `placement_order` |
| 分列 | 按摆放序，每个格子进**当前最矮的那一列**（并列取最左）= LPT | `pack_columns` |
| 列数 | 全部候选（`k = 1..=capacity`，每个 `k` 先自然宽度、再夹到 `zone_w / k`）里，取 **`min(横向填充率, 纵向填充率)` 最大**的解；平局取列数更少、不夹宽的 | `pick_columns` |
| 落位 | **列从右往左排（右锚定，V85）**：第一列贴便签/工作台一侧，剩余空间留在左边给未归类竖条；**列内撑满列宽（V85）**——列宽 = 该列最宽格，窄格撑到列宽并按新宽度重算高（只撑宽、**不夹窄**）；列内自上而下紧挨，单列超高则二分压列高（格子内部滚，不是整层滚） | `content_plan_in` ④ + `fit_column_heights` |
| 带下空间 | 挂件带（便签列）**下方**那条带也归收纳区，但**只在上面那条排不下时才用**，且左沿必须接在上面那条的右边（保住全序 ⇒ 幂等） | `content_plan_with_lower_band` |

**幂等是算出来的**：摆放序是内容的纯函数（与 `LayoutMode`、当前坐标全无关）⇒
尺寸没变 ⇒ 序没变 ⇒ 落位一字不差。不需要「吸附 / 哨兵 / 读序」这类几何补丁。

**列数判据是两代用户反馈合成的**（V84 定稿）：

- **09-23（V71）**：真机 3 个格子（18 / 8 / 8 项、收纳区 637 宽），`k = 2` 让「文档」
  独占第一列、下方空掉 501px，另外两个挤在第二列 —— 用户原话「你看整体效果怎么还是
  **补补丁一样**的」。⇒ 不能只顾少列：**纵向空一半**的解要淘汰。
- **09-29（V84）**：真机 6 个格子 920×968 排成 5 列、占高只有 717，每列 ~176px ——
  用户原话「**搞成那么多列，却空了大量的空白，格子宽度反而压缩到文件名都看不清了**
  **这部分完全可以合并到一列里面**」。⇒ 也不能铺满列数：**横向铺满、纵向空一半**的解
  同样要淘汰。

`min(横, 纵)` 同时否掉这两个方向的畸形；平局时 `k` 小的、不夹宽的先到先得。
「夹宽度必须同时按新宽度重算高度」（`box_height_at`）的口径不变 —— 前端按宽度渲染，
几何不自洽就会「后端算得下、前端还是滚」。

### 1.2 多显示器：**只算主显示器**（V83 定稿）

**策略**：挂件窗**严格等于主显示器工作区**（物理像素），绝不跨屏。副屏幕上不出现
Handy 的任何窗口。上面那张「六区」图的一切几何 —— `work_w × work_h`、各区坐标 ——
一律以**当前主显示器的 `rcWork`** 为坐标系原点与尺寸。

**为什么不做「每屏各按自己的分辨率铺一份」**：

1. **系统层面做不到「主屏接管、副屏保留原生图标」**。桌面图标视图
   （`SHELLDLL_DefView` → `SysListView32`）是**一张横跨整个虚拟桌面的单一视图**，
   只能**整体**显示 / 隐藏。想接管就全接管，想共存就全共存，「只藏主屏那半张」
   没有任何 API 能做到。
2. 便签 / 工作台 / 未归类竖条都是**单实例**语义。双屏各铺一份立刻产生
   「同一份内容到底在哪块屏」的歧义，而这类歧义最终会变成「我的便签丢了」。
3. 双屏各铺需要**每屏一个窗口**：WebView2 窗口跨不同缩放的屏会渲染模糊、尺寸跳变，
   每块屏还得各自维护命中区域、Z 序锚点、接管自愈。这是一个**独立特性**，
   不该混在修 bug 里做。

**副屏是完全原生的**（这是副产品，正好是我们一直要的）：那里没有我们的窗口，
右键 / 新建 / 拖拽 / 双击改名全都不经过 Handy。接管期间副屏的**原生图标**会被一起收起
（原因见第 1 条）—— 这是平台限制，不是取舍。

#### 几何是**实时算**的，不持久化（这条是硬不变量）

```
主显示器 rcWork（物理像素）──► sync_overlay_bounds() ──► 窗口位置 + 尺寸
                                        │
                                        └─► 变了就广播 grid:bounds-changed ─► 前端重排
```

- **真源**：`primary_work_area()` = `app.primary_monitor().work_area()`，物理像素。
- **对齐**：`sync_overlay_bounds()`，幂等；位置与尺寸分开判、**带 2px 容差**
  （非整数缩放下 `SetWindowPos`/`GetWindowRect` 会差 1–2px，严格相等会变成
  「每秒纠正一次却永远纠正不动」的死循环）。连续 5 次仍不一致 ⇒ 退避 5 分钟。
- **调用点**：① `ensure_overlay_window` 复用分支（**每次启动/每次显示都走这里**）；
  ② 新建窗口 build 之后、`show()` 之前（逻辑像素换算有取整误差，贴一次物理边界）；
  ③ 保险轮询线程每 **40 拍 ≈ 1 秒**复核一次（**用户插上外接屏时不会有人去点「整理」**，
  没有这条就永远不会重新对齐）。
- **布局**：`layout_work_size()` **优先问主屏**，问不到才退回窗口尺寸 —— 反过来写会在
  「接上第二块屏」那一瞬间按旧尺寸排一次、纠正后再排一次，用户看到格子抖一下。

#### ⚠️ 曾经的坑：把几何持久化（V83 修，勿重犯）

V83 之前：前端挂载时读一次 `scaleFactor`，之后窗口 `moved` / `resized` 停稳 500ms 就
`grid_geometry_set` 写进 `grid_meta.overlay_geometry`，开窗时 **DB 优先**。

单屏机器上一直看不出问题，**接上第二块屏**就炸：

1. 显示器配置变化 ⇒ Windows/tao 移动甚至改掉窗口尺寸（DPI 变了要重排）⇒ 触发 `resized`；
2. 前端那次换算用的是**挂载时取过的旧 `scaleFactor`** ⇒ 用过期 DPI 把物理尺寸换成逻辑
   尺寸存库，存进去就是个错值；
3. 从此开窗一律按这个错值 ⇒ **永久锁死**。用户 09-28 截图：内容全挤在 `1138×608`
   的角落里，屏幕右侧近 800px、下方 400 多 px 全空。

而窗口是 `resizable(false)` + `decorations(false)`，**用户没有任何调整它的途径** ——
持久化它只有害处。现在 `grid_geometry_get` / `grid_geometry_set` 连同 `GridGeometry`
结构体都**已删除**，历史脏键由 `drop_legacy_geometry()` 在每次开窗时清掉。

**回归防线**：`scripts/regression/test-drag-pointer.mjs` 的 ⑯ 段锁住「几何只由主屏实时决定」
—— 禁止前端再出现 `gridGeometrySet`、禁止开窗路径再读 `grid_meta.overlay_geometry`、
要求三个对齐调用点齐全。

## 2. 桌面模式状态机（再逻辑）


### 2.1 唯一真源

`grid_meta.overlay_visible`（Rust 常量 `META_KEY_OVERLAY_VISIBLE`）是**唯一真源**，
对外表现为 `DesktopMode`：

| 模式 | `overlay_visible` | 触发路径 |
| --- | --- | --- |
| **`On`**（桌面整理开启） | `1` | ① 一键整理；② 工具栏「显示」；③ 托盘「桌面整理：显示/隐藏」；④ 桌面右键「打开 Handy 桌面整理」（`--show-grid`）；⑤ 启动期恢复 |
| **`Off`**（桌面整理关闭） | `0` | ① 工具栏「隐藏」；② 托盘同名项；③ 关闭接管偏好 |

**除这两个值以外，任何地方不得再维护第二份「桌面当前是什么样」的判断。**

### 2.2 派生表（谁在什么模式下是什么样）

| 观测量 | `Off` | `On` | 由谁执行 |
| --- | --- | --- | --- |
| 挂件窗（`grid-overlay`） | 可见 | 可见 | `show_overlay` / `show_launcher_only` |
| 格子 / 竖条 / Dock | 不渲染（`contentHidden = true`） | 渲染 | 前端按 `status.engaged` |
| 工具栏 ⑥ | 显示且可交互 | 显示且可交互 | 前端常驻 |
| 系统桌面图标 | **必须显示**（`takeover_icons(false)`） | 隐藏（`takeover_icons(true)`，受 `takeover` 偏好支配） | Rust |
| 挂件窗纵深 | 桌面正上方 | 桌面正上方 | **桌面层保险**（§2.4） |

### 2.3 不变量（实现必须满足，评审按条查）

- **I1 `Off ⇒ 原生图标可见`**。禁止任何自愈路径在 `Off` 态隐藏图标。
  > 历史缺陷（V45 装机实测）：`grid_overlay_hide` 会交还图标，但 3 秒后的
  > `reassert_takeover` 只看「接管偏好」不看 `overlay_visible`，于是又把图标藏回去
  > —— 格子收起 + 图标藏起来 = **空桌面**。V46 起 `reassert_takeover` 必须先读
  > `overlay_visible`。
- **I2 `On ⇒ 挂件窗可见且在桌面正上方`**。由桌面层保险保证，检测间隔 ≤ 1s、
  纠正一次到位、退避上限 5s。
- **I3 挂件窗恒可见**：`Off` 态也只收「内容」，窗与工具栏留在桌面上
  （否则「隐藏后没有任何入口能再打开整理」是死路，V43 用户实测）。
- **I4 窗口显隐与图标显隐同源**：两者都从 `DesktopMode` 派生，不允许各自判断。
- **I5 绝不移动用户文件**：桌面层的所有操作都只操作**引用登记**与**呈现**。

### 2.4 桌面层保险（Desktop Band Insurance）

挂件窗不是桌面的子窗口（`SetParent` 跨进程被系统拒绝，已在
`scripts/audit/zorder-probe.py` 的实验里确认），所以它只是一个「被刻意压在
所有普通窗口之下、桌面之上」的顶层窗。**任何时刻它都可能被系统挪走**：
用户点击桌面空白处（桌面窗口被激活）、Win+D、Explorer 重建、第三方桌面工具抢层。

保险的做法是**周期性把层级摆回去**，而不是指望一次摆放永久有效：

| 环节 | 参数 | 说明 |
| --- | --- | --- |
| 采样 | `POLL_INTERVAL_MS = 25` | 已有的光标轮询线程顺带做，不新开线程 |
| 判定 | `z_verdict()` | 从自己往下走，碰到桌面宿主 ⇒ `InDesktopBand`（正确） |
| 检测间隔 | `REASSERT_INTERVAL_SECS = 1` | 旧值 3s；用户感知的「桌面没了」就是这么长 |
| 纠正 | `place_above_desktop()` | **单步 `SetWindowPos(HWND_BOTTOM)`**（见下） |
| 退避 | `REASSERT_GIVEUP_BACKOFF_SECS = 5` | 旧值 **300s** —— 一旦连续失败，用户要等 5 分钟 |

**纠正动作的正确形式（V47 修正，V46 结论作废）**：

`SetWindowPos(hwnd, hWndInsertAfter, ...)` 的 `hWndInsertAfter` 语义是
「排在 hwnd **前面**（即更靠上）的那个窗口」，也就是**把 hwnd 放到它下面**。

- V46 的结论是「只保留单步 `SetWindowPos(hwnd, HWND_BOTTOM)`」，
  依据是「`HWND_BOTTOM` 落在所有普通窗口之下、桌面之上」。
- **这个前提是错的**：它默认**桌面宿主永远待在普通窗口带的最底下**。
  用户按 **Win+D / 点「显示桌面」**时，Shell 会把 `Progman` 抬到该带的最顶上 ——
  它正是靠这一手让所有窗口"消失"的。这时再沉底，只是把挂件层压到 `Progman`
  **下面**：桌面干干净净，就是用户报的「win+D 之后桌面什么都没有了，连原桌面都没有」。
  更糟的是判据也判不出来 —— 从挂件层往下走**找得到** `Progman`（它在下头），
  于是 `z_verdict` 报 `InDesktopBand`，自愈一次都不触发。

所以要表达的不是「沉到底」，而是**不变量本身**：挂件层紧贴桌面宿主正上方。

```rust
let anchor = GetWindow(host, GW_HWNDPREV);           // 宿主正上方那一层（同 band 内）
SetWindowPos(hwnd, anchor, 0,0,0,0, SWP_NOMOVE|SWP_NOSIZE|SWP_NOACTIVATE);
```

- `GW_HWNDPREV` 只在**同一 band 内**取，不会跨到 topmost；
- 把挂件层插到 `anchor` **下面** ⇒ 正好落在宿主正上方，**宿主被抬到哪儿都成立**；
- 同样幂等、可反复调用；`anchor` 为空（宿主已在本带顶端）时退回 `HWND_BOTTOM`。

**纠正后必须当场复验**（V47）：`已摆回桌面层` 只说明"调用没报错"，不说明真的摆对了。
`place_above_desktop` 之后再跑一次 `z_verdict`，仍不对就写
`摆回桌面层后复验**仍不对**`。这条日志是分辨「判据错」还是「环境不认」的唯一依据。

### 2.5 交互路径（点一下会发生什么）

| 用户动作 | 结果 |
| --- | --- |
| 点桌面空白 | 桌面窗口被激活，挂件层可能被挪走 → **保险在 1 秒内摆回**，用户不应察觉 |
| 点格子里的条目 | 打开原文件（`grid_open_path`），不动文件 |
| 右键格子 / 条目 / 竖条 / Dock | 原生 Shell 右键菜单（`grid_overlay_menu` / `shell_context_menu`） |
| 点工具栏「工具」 | 右侧抽屉 ④ 落在「工具」页签（实心窗，不弹对话框） |
| 抽屉里点一个工具 | **抽屉内就地打开该工具本体**并加宽到「工具窗」形态；标题栏提供「在控制台打开」 |
| 点工具栏「隐藏」 | `Off`：交还图标 + 收内容，**工具栏留下**（I1 / I3） |
| 退出 / 托盘退出 | `ExitRequested` + `Exit` + `app_quit` 三处恢复原生图标 |

### 2.6 可交互性：命中区是**白名单**（V47 补，此前是最大的交互缺陷源）

挂件窗整窗默认 `set_ignore_cursor_events(true)`（穿透），Rust 轮询按**前端上报的命中区**
决定何时切回可交互。于是：**没被上报的矩形 = 不可点击**。这条白名单必须完整，
否则用户看到的是「东西在那儿，但点不动」。

历史上漏掉的正是**右键菜单**：菜单锚在右键落点上，经常有一半探出格子矩形之外，
那半边落在未上报区域 → Rust 判定光标没命中 → 整窗切回穿透 → 点击直接漏到桌面。
用户描述得极准：「右键刚打开这个菜单的时候几个菜单都不能点击……鼠标离开各自区域再回去
就可以点击」——"回去"指回到格子矩形内，那只是一种**碰巧**恢复。

规则（V47 起）：

1. 四个右键菜单的矩形**必须**和格子 / 工具栏 / 竖条 / Dock / 抽屉一起上报；
   菜单开合要进 `regionsKey`，触发重新上报（矩形尺寸只能渲染后量）。
2. 菜单开着期间**再显式按住** `grid_set_interactive(true)` —— 命中区上报走 25ms 轮询，
   天然有一拍延迟，而"点了就要能用"的东西不能把可用性押在轮询上。
3. 菜单**鼠标离开即关闭**（300ms 宽限）。
4. **新增任何浮层组件（菜单 / 气泡 / 弹层）时，必须同步登记到命中区** ——
   这是本文件唯一一条「加组件时的强制动作」。

### 2.7 拖放：两个拖拽源必须共用同一套状态（V47 补）

拖拽期间根画布的 `pointerEvents` 由 `itemDragging` 决定（`auto` / `none`）。
历史上只有「拖格子里的条目」置位，**「从左侧竖条拖」忘了置位** ——
于是从竖条起拖时整层仍是穿透态，根画布不再 `preventDefault`，
浏览器判定「此处不可放置」并把光标画成**圆圈禁止**。
用户看到的正是「桌面上的图标所有的都不能拖动了，直接是圆圈禁止状态」。

规则：`startItemDrag` 与 `startLooseDrag` **必须对称** —— 都置 `itemDragging`、
都设 `effectAllowed = 'copyMove'`、都由 `endItemDrag` 收尾；根画布的
`onDragOver` / `onDrop` 必须同时认两个 ref。

### 2.8 挂件区按**整列**保留（V47 补）

挂件（日历 / 便签）此前只把自己**那块矩形**当禁区，流布器于是"见缝插针"，把收纳格
塞进日历正下方那截余量（真实数据：`安装包` / `图片` 落在 `y=694`，正好压在日历下沿
`670` 之下）。用户原话：「宽度不一致而且跑到日历下面了，看图片很不协调呢」。

规则：**凡是与挂件区相交的列，自上而下全高都归挂件区**，收纳格一律不进。
于是收纳格只落在挂件区左边的列里，同列左边缘对齐 ⇒ 上下对齐、宽度一致。
本机实测（1707×912，列宽 300）：日历占 2 列，收纳格剩左侧 2 列。

### 2.9 新建挂件后必须重排一次（V47 补）

`grid_box_upsert` 不给坐标时落默认值 `(32, 32)`，而布局只在一键整理时才跑 ——
用户新建的两个便签就**直接压在左侧「不整理」竖条那条禁区上**（真实数据
`便签`/`便签 2` 在 `(32,32)` 与 `(32,276)`）。用户原话：「添加便签后这个位置放在这里
也不合适，便签的位置需要自动放在合理的位置上」。

规则：新建挂件后调用 `grid_relayout`（**只归位、不扫描**，语义比一键整理轻），
走同一条布局流水线，等价于"立刻把不变量恢复一遍"。新建挂件时的坐标**不再由前端硬算**。

## 3. 工具呈现模型（桌面抽屉）

用户在 V45 给的反馈：「工具箱这些工具类**不要透明了**，透明有问题」「工具搜索
应该放在右侧，直接搜索获取，而不是打开额外的对话框」「**大小也不太友好**」。

### 3.1 一块面板，两个页签

- **工具页签**：顶部搜索 → 空查询时按分类分组浏览 → 点一项，**面板原地**换成
  工具本体（顶部一条「返回」），全程不弹第二个框；
- **快捷页签**：应用入口 + 我的快捷方式 + 系统入口（白名单 `sys_action_run`）。

### 3.2 实心化规则（V46）

| 位置 | V45 | V46 |
| --- | --- | --- |
| 抽屉外壳 | `bg-neutral-900/93 + backdrop-blur-2xl` | **`bg-neutral-900`（不透明）**，仅保留 1px `ring-white/15` 分界 |
| 工具本体底 | `bg-neutral-950/45` | **`bg-neutral-950`（不透明）** |
| 工具栏 / Dock | `/75`、`/60` + 模糊 | `/95`、`/92`（去模糊，保证可读） |

半透明在桌面上是**可用性缺陷**而不是美化：壁纸是高对比照片时，
文字与图标按钮的可读性、可点性都会掉下来。

### 3.3 尺寸规则

抽屉按「装得下一个真实工具」定尺，而不是按「浮层」定尺：

```
SIDE_PANEL_SHELL = absolute right-[252px] top-4 bottom-[92px] z-40
                   w-[min(820px, calc(100vw-300px))]
```

- 宽度下限保证分栏类工具（JSON 格式化、文本对比）左右两栏都撑得开；
- 右缘避开工具栏 ⑥（实宽约 236px，**不要按记忆里的 92px 估**）；
- 下缘避开 Dock ⑤：Dock 最宽 `60vw` 且居中，**横向会跨到面板下方**，
  所以只能靠纵向让位（Dock 高约 44px + 距底 20px ⇒ 面板停在 92px）。
  别用「Dock 在中间、面板在右边」推断不重叠；
- 列表行高、标题字号同步上调一档，避免「14 寸屏上要凑近看」。

### 3.4 进控制台

工具窗标题栏固定提供 **「在控制台打开」**：调 `desktop_open_view(<工具/模块 id>)`
—— 显示主窗口 + 发 `handy:navigate` 事件（与顶部贴条同一套机制，ADR-8：
视图状态每窗口独立）。桌面负责「顺手用一下」，控制台负责「完整界面 / 多一点空间」。

### 3.5 便签 Markdown 编辑器（V47）

用户原话：「便签页面的样式需要优化完善，尤其是 markdown 编辑器各种格式支持，
现在 `---` 分割线不支持，你看还有其他那些 markdown 语发没有支持，
还有 code ``` 输入貌似只能输入一行内容，不能自动根据我的输入扩展行数」。

两条都已定位到**实现缺陷**，不是解析器能力不足：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| `---` 分割线"不支持" | CommonMark 的 **setext 规则**：`---` 紧跟在段落行下面时是「二级标题下划线」，渲染成 `<h2>`，分割线消失 | `renderMarkdown` 前做一次**规范化**：`-{3,}` 独占一行且上一行非空 → 先补空行，落成 `<hr>`。只动连字符（`***`/`___` 本来就永远是 `<hr>`）；已验证不误伤表格分隔行 `\|---\|---\|` |
| 代码块只能写一行 | `AUTO_PAIRS` 把反引号也当"成对符号"：敲第一个 `` ` `` 就补出 ` `` `，第三个反引号命中"右侧已有闭符号就跳过"，**三个反引号在同一行被就地闭合** | 特判「补上的第三个反引号」= 要代码块 → 摊成 ` ``` ` / 缩进 / ` ``` ` 三行并把光标放进中间；缩进跟随当前行，列表项里也能插 |
| 代码块内回车被塞 `- ` 前缀 | 回车处理器只认列表模式，不认围栏上下文 | `handleEnter` 开头加守卫：光标前围栏行数为**奇数** ⇒ 在围栏内 ⇒ 一律纯换行 |

**回归防线**：`src/lib/markdown.ts` 的规范化是纯函数、无 DOM 依赖，改动后必须用
`node -e` 跑一遍那五类输入（贴正文 / 已有空行 / 文件开头 / 表格分隔行 / 连续两条），
确认表格分隔行没被误伤 —— 这是最容易写坏的一条正则。
