## 一、v2 已决策（团队按此推进，可回改）

| # | 决策项 | 采用值 | 理由 | 来源 |
| --- | --- | --- | --- | --- |
| V0 | ✅ **产品名（已定）** | **Handy · 顺手**（英文 Handy / 中文 顺手）；主张「方便，而非全面」 | 与产品定位气质一致、对普通办公人群零理解成本；备选 万象/OmniDesk 留档 | PRD §2 |
| V1 | **跨平台** | Windows 10/11 + macOS 12+（同一套代码基座），Linux 后续评估 | 用户明确要求双平台；Tauri 2 原生跨平台，成本低 | PRD H1 |
| V2 | **一键安装** | Win 出 `.msi`+`.exe`(NSIS)，mac 出 `.dmg`；终端用户零环境部署 | 用户明确要求「不可能让用户自己部署环境」 | PRD H2 |
| V3 | **架构可扩展** | 「**模块 + 功能**」双层注册（`ModuleMeta` + `CommandMeta`）+ 统一扩展点；新增功能**不改框架** | 用户要求「工具可扩展易扩展」，为做大做强与商业化留位 | PRD H3 / ADR-6 |
| V4 | **受众扩容** | 主力人群 = 普通办公人员；产品名与信息架构禁用「运维/百宝箱/工具箱」窄词 | 用户原话「格局小了吧，普通办公人员也可用」 | PRD H4 |
| V5 | **产品形态** | 从「工具箱」扩为 **11 模块效率套件**（工具箱只是其一） | 用户要求纳入桌面整理、便签等，不限便携工具 | PRD §3 |
| V6 | **MVP 范围** | 统一入口 + M1 工具箱(8 子工具) + M2 桌面整理(基础) + M3 便签/待办 + M4 剪贴板 + 双平台一键安装 | 克制、能打动大众；截图/文件处理/系统优化/OCR/PDF/插件系统不做 | PRD §5 |
| V7 | **持久化（修订 v1）** | **SQLite 为主数据层**（便签/待办/剪贴板/历史/整理计划）；`store`(JSON) 降级为仅配置态 | 剪贴板高频写、便签高频局部更新、需 FTS 检索；JSON 全量重写会放大且易损 | ARCHITECTURE ADR-7 |
| V8 | **多窗口** | 窗口管理器 + `WindowKind`；便签一便签一窗（无边框/置顶/几何持久化） | 便签/桌整/截图需独立窗口 | ADR-8 |
| V9 | **平台差异处理** | 差异收敛到 `src/platform/` 与 `src-tauri/src/platform/{windows,macos}`；业务代码不写平台分支 | 保证一套业务代码双端跑 | ADR-5 |
| V10 | **打包与签名** | Win 用 WebView2 bootstrapper（保体积）+ 缺失检测；mac 走 Developer ID 签名 + 公证 + staple | 对齐体积目标与 mac 装机要求 | ADR-9 |
| V11 | **商业化底线** | 核心「效率与整理」**永久免费**；Pro 落在截图/OCR/PDF/密码管理/批量等**增强能力**；无广告、无捆绑、不诱导付费 | 不伤害免费体验 | PRD §7.3 |
| V12 | **商业化主模式** | 早期以 **买断制 Pro** 为主；订阅待出现云/同步服务后再引入 | 降低用户决策成本 | PRD §7.2 |
| V13 | **扩展分层节奏** | 本期只做 **L1 内置模块** + 扩展点/License **接口预留**；L2 官方扩展包、L3 第三方插件不在本期 | 插件是放大器也是风险源，规模与安全机制成熟前不放开 | PRD §6.2 / ADR-10 |
| V14 | **默认快捷键** | Win `Alt+Space`；mac `Option+Space`（避开 Spotlight 的 `Cmd+Space`） | 平台冲突规避 | PRD Q9 |
| V15 | **深色主题** | MVP 先浅色扁平，深色用 `dark:` 令牌预留 | 聚焦 MVP | TASKS AQ8 |

## 二、定案记录（2026-09-13 团队按最佳方案裁定 · 用户已全权授权）

> 用户原话：「所有的待定的内容你自己按照最佳方案自己选定就可以了，全权交给你来执行」。以下为**最终裁定，不再需要用户确认**。

| # | 问题 | ✅ 定案 | 关键理由 | 影响面 |
| --- | --- | --- | --- | --- |
| D1 | **macOS 优先级** | 与 Windows **同步做** | 跨平台是产品硬需求（H1）；Tauri 同一套代码基座，延后反而要重做平台适配层 | 开发与 CI 双平台 |
| D2 | **免费 / 付费边界** | 核心「效率与整理」**永久免费**；Pro = 截图/OCR/PDF/密码管理/批量等增强能力 | MVP 全功能 `tier=free`，先做口碑与规模 | 授权接口占位 |
| D3 | **第三方插件市场（L3）** | **早期不做**，仅预留扩展点 | 安全审核与维护成本高，规模未起时放开是风险源 | 架构预留即可 |
| D4 | **账号 / 云同步** | MVP **不做**，纯本地 | 与「离线 · 隐私」定位一致，且免后端成本 | 无后端 |
| D5 | **mac 桌面整理强度** | 仅「**文件归类**」，不做桌面图标收纳盒 | macOS 无等价桌面图标 API，降级为文件归类最务实 | M2 工作量可控 |
| D6 | **买断 vs 订阅** | 早期**买断制 Pro** | 降低用户决策成本；订阅待云服务出现再引入 | 商业化 |
| D7 | **Linux 支持** | **Phase 3+ 再评估** | 聚焦双平台质量，不分散精力 | 路线图 |
| D8 | **OCR / PDF 引擎** | Phase 2/3 用**本地引擎** | 与隐私、离线定位一致 | 包体积 |
| D9 | **CI 自动化发版** | 先落**本地构建脚本**，CI 作为增强 | 减少前期卡点，先保证能出包 | V14 |
| D10 | **深色主题** | MVP 先**浅色扁平**，`dark:` 令牌预留 | 聚焦 MVP | 设计令牌 |
| D11 | **自动更新** | 先支持**手动检查更新**；签名密钥/端点在首次发版前再定 | 无发布端点时不硬编码 | V14 |
| D12 | **开发目录** | 代码全部落在 **`D:\_Projects\ops\handy`**（独立项目）；旧 `ops-tools` **只读参考、永不修改** | 用户要求与老项目彻底分开 | 全项目 |
| D13 | **开发环境** | 用户机器已具备 Node v22.22.2 ✅ / npm 10.9.7 ✅ / WebView2 137 ✅ / 管理员权限 ✅；**Rust + MSVC 工具链由团队自动安装** | 用户不懂技术，环境由我们负责；终端用户**零环境**（装包即用） | 开发链路 |
| D14 | **现在开工** | ✅ **立即进入 Phase 1（V01 脚手架起）** | 用户已授权执行 | 进度 |
