## 0. 本轮四条硬需求（不可妥协）

| # | 硬需求 | 对产品的约束 |
| --- | --- | --- |
| H1 | **跨平台** | 必须同时支持 Windows 与 macOS，功能用同一套代码基座；平台差异只做「降级说明」，不做「只支持一个平台」 |
| H2 | **一键安装** | 最终交付 `.exe / .msi`（Windows）与 `.dmg`（macOS）安装包，**用户双击安装即用**，终端用户零环境部署（不得出现「先装 Node/Python/Rust」等要求） |
| H3 | **可扩展** | 架构上必须能**持续低成本地新增功能模块**，为「做大做强 + 商业化」预留空间 |
| H4 | **受众扩容** | 产品不能只服务运维/研发，**普通办公人员**也要能用、爱用；产品名与信息架构不得使用「运维」「百宝箱」等窄词 |

## 1. 产品重新定位

### 1.1 一句话定位

> **一个常驻托盘的跨平台桌面效率套件：把「桌面整理、便签、剪贴板、截图、文件处理、系统增强、以及一整套随手即用的小工具」收进同一个入口，一个快捷键呼出，双击安装即用，离线可用、隐私不外泄。**

- 对普通办公人员：**它是「桌面管家 + 效率百宝助手」**——收拾桌面、随手记事、找回剪贴板、截图标注、批量处理文件。
- 对运维/研发：**它仍是那把「秒开的工具箱」**——完整继承 v1 的 30+ 高频工具。
- 底层：**一个可不断加模块的平台**，新功能 = 新模块 = 新价值 = 商业化筹码。

### 1.2 定位升级对照（v1 → v2）

| 维度 | v1（旧定位） | v2（新定位） |
| --- | --- | --- |
| 一句话 | Windows 运维/开发工具箱 | **跨平台桌面效率套件 / 办公增强助手** |
| 平台 | 仅 Windows | **Windows + macOS** |
| 受众 | 运维/研发（90%） | **普通办公人员（主力）+ 运维/研发 + 学生/自由职业** |
| 边界 | 便携小工具集合 | **多模块平台**（整理/便签/剪贴板/截图/文件/系统/安全/媒体/办公） |
| 交付 | 绿色运行 | **一键安装包（exe/msi/dmg）** |
| 扩展 | 新增工具=加组件 | **新增模块 / 官方扩展 / 远期第三方插件市场** |
| 商业 | 未提及 | **免费 + Pro 分层 + 插件市场（构想）** |

### 1.3 目标人群分层

| 层级 | 人群 | 占比预估 | 核心诉求 | 对应主推模块 |
| --- | --- | --- | --- | --- |
| **主力（新）** | 普通办公人员（行政/人事/销售/财务/教师/文员） | **50%** | 桌面别乱、随手记事、文件别乱、快捷键会用、别折腾 | 桌面整理、便签/待办、剪贴板、截图、文件处理、媒体小工具 |
| 次要 | 运维 / 研发 / DevOps | 30% | 秒开工具、离线、隐私、系统级能力 | 效率工具箱、系统优化、安全隐私 |
| 边缘（增量） | 学生 / 自由职业 / 设计师 / 内容创作者 | 20% | 截图标注、格式转换、素材整理、专注 | 截图套件、媒体小工具、办公增强 |

> **取舍观点**：v2 的**增长引擎是「主力」这一层**，因此 MVP 必须包含「桌面整理 + 便签 + 剪贴板」这三个**大众一见就懂**的模块；运维工具是**留存与口碑**的护城河，但不是**拉新的钩子**。

### 1.4 差异化：为什么装我们，而不是一堆零散小软件

| 差异点 | 零散小软件的问题 | 我们的一体化价值 |
| --- | --- | --- |
| **统一入口** | 装了 10 个软件，10 个托盘图标、10 套快捷键、10 次更新 | **一个快捷键、一个托盘、一个设置中心**，功能可搜可换 |
| **一体化数据** | 便签/剪贴板/待办各自为政，互不联通 | 剪贴板内容可**一键转便签/待办**；截图可**存入便签/文件处理** |
| **离线 + 隐私** | 大量小软件要联网、传云、带广告与捆绑 | **纯本地计算、默认不联网、无广告无捆绑、数据不出本机** |
| **一键安装** | 很多工具要自行配置、绿色包解压、命令行部署 | **双击安装即用，零环境依赖**（Tauri 复用系统 WebView，无运行时包袱） |
| **持续扩展** | 单一工具做完就停更 | **模块化平台**，官方持续加模块，远期可装第三方插件 |
| **轻量常驻** | Electron 类动辄 200MB+ 内存 | Tauri：**包小、内存低、秒开**（复用系统 WebView） |

> **一句话**：别人卖的是「一个个工具」，我们做的是「一个会不断长大的桌面助手」。

## 2. 产品命名（已定）

原则：**远离「运维 / 百宝箱 / 工具箱」等窄词**，名字要能装下「效率套件 + 未来商业化」，同时表达「**顺手好用**」而非「大而全」。

### 2.1 最终命名

> # ✅ **Handy · 顺手**

| 项 | 值 | 说明 |
| --- | --- | --- |
| 中文名 | **顺手** | 「顺手拈来」——直白表达随手好用；口语化、传播强、最贴普通办公人群 |
| 英文名 | **Handy** | 随手可得、轻便趁手；跨语言无障碍，利于传播与出海 |
| **命名主张** | **方便，而不是全面** | 产品价值是「随手就用的那一下」，不是「功能列表的长度」 |
| 应用标识 | `com.handy.desktop` | 包名 / 安装包名 / 托盘名 / 图标统一用 Handy 品牌 |
| 数据文件 | `handy.db`（SQLite）· `settings.json`（配置） | 见 `02-architecture/ARCHITECTURE.md` §7 / §8 |

**选择理由**：产品定位是「**方便**」而不是「**全面**」——`Handy · 顺手` 与这一定位气质完全一致，对普通办公人群**零理解成本**、一说就懂；`万象 / OmniDesk` 平台感更强，但暗示「大而全」，与命名主张相悖，故降为备选留档。

### 2.2 候选与推演留档

| 候选 | 中文 | 英文 | 寓意 | 风格 |
| --- | --- | --- | --- | --- |
| ✅ **采用** | **顺手** | **Handy** | 「顺手拈来」——随手好用的直白表达 | 亲和、大众、易记 |
| 备选 | 万象 | OmniDesk | 「包罗万象」，平台感强、商业化天花板高，但气质偏「全面」 | 大气、平台感 |
| 备选 | 流匣 | FlowKit | 「效率之流 + 可插拔的匣」，强调工作流与模块化/插件市场 | 极客、可扩展 |
| 备选 | 日伴 | DayMate | 「办公日常的伙伴」——陪着你完成一天的琐事 | 温暖、订阅品牌友好 |
| 备选 | 方糖 | Cube | 模块化隐喻（一块块功能拼成桌面助手），视觉 IP 易做好看 | 年轻、轻巧 |

- **明确排除**：任何含「运维 / 工具箱 / 百宝箱 / Toolbox」的名称——这与 H4 直接冲突。

> 下文正文统一以「**本产品**」或「**Handy**」指代。

## 3. 模块矩阵（核心）

**模块划分总览**：产品由 **11 个功能模块** 构成，全部挂在**同一个命令面板入口 + 托盘常驻**之下。

| 模块 | 定位 | 目标用户 | 优先级 | 跨平台可行性备注（macOS） |
| --- | --- | --- | --- | --- |
| **M1 效率工具箱** | 承接 v1 的 30+ 随手即用小工具（时间戳/JSON/编码/密码/哈希/网络/运维等） | 运维研发为主，大众部分可用 | **P0** | ✅ 纯计算类全平台一致；进程/端口类需各自原生实现 |
| **M2 桌面整理** | 桌面图标/文件自动归类、一键整理、桌面收纳盒 | 普通办公（新主力） | **P0** | ⚠️ macOS 桌面图标受系统限制，需 Access（辅助功能）/AppleScript，实现差异大，先做「文件归类」降级 |
| **M3 便签·待办·提醒** | 桌面便签、任务清单、定时提醒 | 全体（大众刚需） | **P0** | ✅ 全平台一致；系统通知走各自 API |
| **M4 剪贴板增强** | 历史、置顶、搜索、智能识别（JSON/JWT/URL/时间戳） | 全体 | **P0** | ✅ 一致；macOS 需处理「剪贴板访问权限」首次授权提示 |
| **M5 快速启动·全局搜索** | 命令面板、应用/文件快速搜索启动 | 全体 | **P1** | ⚠️ macOS 需 Spotlight 索引 API / 文件系统遍历，权限受限；默认键需避开 `Cmd+Space` |
| **M6 截图·贴图·标注·OCR** | 截图、钉图/贴图、标注画框、文字识别 | 办公/设计/学生 | **P1** | ⚠️ 需「屏幕录制」权限（macOS 隐私限制）；OCR 走本地引擎 |
| **M7 文件处理** | 批量重命名、编码/换行符转换、重复文件查找、磁盘空间分析、大文件清理 | 办公 + 运维 | **P1** | ✅ 大部分一致；磁盘分析/提权操作需各自适配 |
| **M8 系统优化·增强** | 开机启动项管理、右键菜单增强、系统信息 | 大众 + 运维 | **P1**（信息 P1 / 优化 P2） | ⚠️ macOS 无「注册表/右键菜单」概念，改为「登录项管理 + 访达扩展」，部分能力降级 |
| **M9 安全与隐私** | 敏感数据脱敏、文件加密、（可选）密码管理 | 全体（脱敏）/ 隐私敏感者 | **P1**（密码管理 **P2**） | ✅ 加密/脱敏一致；密码管理需走系统钥匙串（Keychain） |
| **M10 媒体小工具** | 图片压缩、二维码生成/解析、PDF 轻处理、格式转换 | 办公/学生/运营 | **P1** | ✅ 基本一致；PDF 建议引入跨平台原生库 |
| **M11 办公增强·协作** | 会议记录/计时、跨设备传文件（局域网/二维码）、快捷片段（文本扩展）、专注计时 | 办公/学生 | **P2** | ⚠️ 跨设备传文件需局域网；快捷片段在 macOS 需辅助功能权限 |

### 3.1 模块内功能明细

**M1 效率工具箱**（继承 v1，绿=P0/蓝=P1/黄=P2）

| 分类 | 功能 | 优先级 |
| --- | --- | --- |
| 文本与数据 | JSON 格式化 / 文本差异对比 / CSV↔JSON / YAML↔JSON / SQL 格式化 / 数据脱敏 | 🟢P0×2 · 🔵P1×4 |
| 编码与格式 | 时间戳转换 / Base64 / URL 编解码 / 进制转换 / 字符串转义 / 编码检测 | 🟢P0×2 · 🔵P1×4 |
| 加密与安全 | 密码生成 / 哈希（文本+本地文件）/ JWT 解码 / AES / RSA / OTP / Bcrypt | 🟢P0×3 · 🔵P1×4 |
| 网络与 API | IP/CIDR 规划 / 本地端口查询 / 常用端口 / 带宽计算 | 🟢P0×2 · 🔵P1×2 |
| 开发与运维 | Cron 预览 / Docker↔Compose / 命令速查 / 配置生成器 / HTTP 代码生成 | 🟢P0×2 · 🔵P1×5 |
| 媒体 | 图片压缩 / 二维码（并入 M10） | 🔵P1 |

> 详细逐项清单见 `TOOLS_INVENTORY.md`，v2 **不删减 v1 已定工具**，仅将其纳入「M1 模块」。

**M2 桌面整理**：一键整理（按类型/日期/项目归位）｜规则化自动归类（图片→图片夹、文档→文档夹）｜桌面收纳盒（把图标拖进盒子）｜整理前预览 + 一键撤销。

**M3 便签·待办·提醒**：桌面便签（置顶/透明/换色）｜待办清单（勾选/截止日）｜定时提醒（系统通知）｜便签↔待办互转。

**M4 剪贴板增强**：历史记录（搜索/置顶/固定）｜智能识别并推荐工具（JSON/JWT/URL/时间戳）｜多格式（文本/图片缩略/文件路径）｜一键转便签/待办。

**M5 快速启动·全局搜索**：输入即搜应用/文件/工具｜拼音首字母匹配｜最近/收藏置顶｜可扩展的「一切皆可搜」入口。

**M6 截图套件**：区域/窗口/全屏截图｜钉图（贴图悬浮）｜标注（框/箭头/马赛克/文字）｜滚动截图（P2）｜本地 OCR 取字。

**M7 文件处理**：批量重命名（正则/序号/前后缀）｜编码/换行符批量转换｜重复文件查找（按哈希）｜磁盘空间分析（谁占了空间）｜大文件/空文件夹清理。

**M8 系统优化·增强**：开机启动项管理（启用/禁用）｜右键菜单增强（Win）/ 访达扩展（mac）｜系统信息（CPU/内存/磁盘/系统版本）。

**M9 安全与隐私**：敏感数据一键脱敏（手机/身份证/邮箱/银行卡）｜文件加密/解密（本地密码）｜密码管理（P2，走系统钥匙串）。

**M10 媒体小工具**：图片压缩（批量/质量可调）｜二维码生成/解析｜PDF 轻处理（合并/拆分/提取页，P2）｜图片格式转换（PNG/JPG/WebP）。

**M11 办公增强·协作**：会议记录/计时｜跨设备传文件（同一局域网 + 二维码/短链）｜快捷片段/文本扩展（输入缩写展开）｜专注番茄钟。

## 4. 办公日常痛点全清单（重点）

## 5. MVP 范围裁定（第一版该做什么）

### 5.1 裁定原则

1. **能打动普通办公用户**：第一眼就要有「这东西有用」的三个模块——**桌面整理、便签、剪贴板**。
2. **克制**：不做截图/文件/系统/媒体/OCR 等重工程模块（放入 Phase 2/3）。
3. **跨平台 + 一键安装**：MVP 就必须同时出 Windows 与 macOS 安装包（否则违背 H1/H2）。
4. **保留 v1 已完成的护城河**：效率工具箱的 P0 工具**不弃**，但只保留「跨平台无争议 + 大众也看得懂」的子集。

### 5.2 MVP 模块组成（6 部分）

| MVP 组成 | 具体范围 | 为什么进 MVP |
| --- | --- | --- |
| **① 统一入口** | 命令面板（快捷键呼出）+ 托盘常驻 + 设置中心 + 收藏/最近 | 所有功能的地基，v1 已设计，成本低、感知强 |
| **② M2 桌面整理（基础版）** | 一键整理 + 预览 + 撤销（先做「文件归类」，macOS 降级） | **大众第一眼钩子**，最能体现「办公增强」 |
| **③ M3 便签·待办** | 桌面便签（置顶/换色）+ 待办清单 + 定时提醒 | **大众刚需**，天天用，留存核心 |
| **④ M4 剪贴板增强** | 历史 + 搜索 + 置顶 + 智能识别推荐 | 高频、感知强、与便签联动（转便签） |
| **⑤ M1 效率工具箱（通用子集）** | 时间戳、JSON、Base64、密码生成、文本差异、URL 编解码、哈希（文本）、二维码 | 继承 v1 投入；覆盖办公+研发通用；跨平台零风险 |
| **⑥ 交付形态** | Windows `.exe/.msi` + macOS `.dmg` 一键安装包；离线可用；代码签名 | H1+H2 硬需求，MVP 必须闭环 |

> **MVP 不做**（明确划到后续）：截图套件、文件处理、系统优化、文件加密、OCR、PDF、跨设备传文件、插件系统。（避免第一版工程摊薄、品质下降。）

### 5.3 MVP 验收清单

| # | 验收项 | 通过标准 |
| --- | --- | --- |
| A1 | Windows 一键安装 | 双击 `.exe/.msi` 完成安装，无需任何命令行/环境配置 |
| A2 | macOS 一键安装 | 双击 `.dmg` 拖入即装，含签名/公证，无「来自身份不明的开发者」拦截 |
| A3 | 命令面板呼出 | 全局快捷键 < 300ms 呼出；可改键；冲突有提示 |
| A4 | 官方模块可用 | 桌面整理、便签、剪贴板、工具箱（8 子工具）四类功能均可正常使用 |
| A5 | 桌面整理闭环 | 一键整理 → 预览 → 确认 → 可一键撤销 |
| A6 | 便签持久化 | 便签/待办跨重启保留；提醒能触发系统通知 |
| A7 | 剪贴板闭环 | 记录最近 100 条；可搜索/置顶/回贴；可一键转便签 |
| A8 | 离线可用 | 断网下所有 MVP 功能正常，无白屏/加载失败 |
| A9 | 隐私底线 | 敏感内容（密码）默认不落盘；无广告、无捆绑、默认不上报 |
| A10 | 轻量常驻 | 托盘空闲内存 < 150MB；安装包体积 < 30MB（Win）/ < 40MB（mac） |
| A11 | 新增模块低成本 | 新增一个「工具型」功能只需加组件 + 注册项，不改框架（可扩展性验证） |
| A12 | 卸载干净 | 卸载后可彻底移除，无残留启动项 |

## 6. 可扩展性需求（产品视角）

### 6.1 目标：新增功能「低成本、可预测」

- **工具型功能**（纯计算类）：新增 = 建 1 个组件 + 注册 1 条元数据 → 自动获得入口、搜索、收藏、历史、复制。**零框架改动**。
- **模块型功能**（便签/桌面整理等带独立界面与系统能力）：以**模块**为单位接入，模块之间通过统一入口与共享数据（便签/剪贴板/文件）联动。
- **系统能力**（跨平台差异）：差异封装在平台适配层，**产品文档只承诺「功能可用」，不承诺「实现一致」**（见第 8 章降级策略）。

### 6.2 扩展能力分层（内置 → 官方 → 第三方）

| 层级 | 说明 | 何时做 | 与商业化 |
| --- | --- | --- | --- |
| **L1 内置模块** | 官方随包发布的模块（本 PRD 的 11 个模块） | 持续迭代 | 免费/Pro 的基础 |
| **L2 官方扩展** | 官方按需下发的独立功能包（如「行业工具包」「PDF 增强」） | Phase 3 起 | **Pro 专属**模块的载体 |
| **L3 第三方插件** | 开放插件接口，允许第三方（含用户）开发并分发（可走市场抽成） | Phase 4，**需用户拍板** | 生态与抽成收入 |

> **分层建议**：**先做扎实 L1，验证 L2（官方扩展包机制），再谨慎开放 L3**。插件系统是「放大器」也是「风险源」（安全、审核、兼容、维护），在用户规模与安全机制成熟前**不建议在早期开放第三方**。

### 6.3 与商业化的配合

- 免费版 = L1 的**核心子集**（保证人人可用）。
- Pro 版 = 解锁**高级模块 / 高级能力**（如批量处理、OCR、PDF、密码管理、跨设备传文件）。
- 插件市场 = 第三方插件的**分发与抽成**通道（L3 阶段）。

## 7. 商业化设计（构想，非最终定价）

### 7.1 免费版 vs 付费版功能分层（建议）

| 能力 | 免费版 | Pro 版（构想） |
| --- | --- | --- |
| 统一入口/托盘/命令面板 | ✅ 完整 | ✅ 完整 |
| M1 效率工具箱（通用子集） | ✅ | ✅ |
| M2 桌面整理 | ✅ 基础（一键整理） | ✅ 高级（规则自动归类、多套方案） |
| M3 便签·待办·提醒 | ✅ 基础 | ✅ 高级（同步、模板、批量） |
| M4 剪贴板增强 | ✅ 基础（含条数上限） | ✅ 无上限 + 更多类型（图片/文件） |
| M6 截图/OCR、M10 PDF、M9 密码管理 | 部分/受限 | ✅ 完整 |
| M11 跨设备传文件 | 受限 | ✅ 完整 |
| 官方扩展包（L2） | 少量 | ✅ 全部 |
| 更新与支持 | ✅ | ✅ 优先 |

> **底线**：**核心「效率与整理」能力永久免费**，付费点落在「**高频但可延展的生产力增强**」，而非把基础功能锁起来。

### 7.2 付费模式（候选，可组合）

| 模式 | 说明 | 适配度 |
| --- | --- | --- |
| **买断制** | 一次性购买 Pro，永久使用当前大版本 | 工具类用户接受度高，**推荐作为主模式** |
| **订阅制** | 月/年订阅，持续更新与同步 | 适合有云同步/持续服务时；早期可弱化 |
| **Pro 解锁高级模块** | 按模块包解锁（如「PDF 包」「OCR 包」） | 灵活，配合 L2 扩展 |
| **插件市场抽成** | 第三方插件销售抽成 | L3 阶段，长期生态收入 |

> **建议路线**：**早期以「买断制 Pro」为主**，降低用户决策成本；**待出现云端/同步类服务后再引入订阅**；插件市场抽成放到生态成型后。

### 7.3 不伤害免费用户体验的底线原则

1. **隐私至上**：数据默认本地、默认不联网、默认不采集，**付费也不以「交出隐私」为代价**。
2. **离线可用**：核心功能**永久离线可用**，不搞「联网才给用」。
3. **不做恶**：**无广告、无捆绑、无诱导付费弹窗**；免费版功能不缩水到难用。
4. **可退出**：卸载干净、可导出数据、订阅可随时取消。

## 8. 跨平台策略（产品视角）

### 8.1 功能差异与降级策略

| 能力 | Windows | macOS | 降级/替代策略 |
| --- | --- | --- | --- |
| 命令面板/快捷键 | 全局快捷键（如 `Alt+Space`） | 全局快捷键，**默认键须避开 `Cmd+Space`（Spotlight）** | mac 默认改用 `Option+Space` 或 `Cmd+Shift+Space` |
| 托盘常驻 | 系统托盘 | 菜单栏图标 | 形态一致，术语与交互按平台习惯 |
| **桌面整理** | 可较自由操作桌面图标 | 桌面图标受系统限制，需辅助功能/脚本，**稳定性差** | mac **降级为「文件归类整理」（操作文件而非图标）**，不承诺「桌面图标收纳盒」 |
| 剪贴板历史 | 直接监听 | 需**剪贴板访问/辅助功能授权** | 首次引导授权；未授权则仅提供「手动读取」 |
| 快速启动/全局搜索 | 开始菜单/文件索引 | 需 Spotlight/文件系统 API，权限受限 | mac 优先「应用启动」，「文件全盘搜索」作为增强 |
| 截图套件 | PrintScreen 生态 | 需**屏幕录制权限** | 首次引导授权；未授权功能不可用 |
| 系统优化 | 注册表/启动项/右键菜单 | **无注册表/右键菜单**，改「登录项 + 访达扩展」 | mac **部分能力降级或不做**，只保留「登录项管理 + 系统信息」 |
| 文件加密/脱敏 | 一致 | 一致 | 无差异 |
| 密码管理 | 凭据管理器 | **系统钥匙串（Keychain）** | 各自走原生凭据存储 |

### 8.2 系统级权限与合规（macOS 重点）

| 事项 | 要求 | 产品影响 |
| --- | --- | --- |
| **代码签名 + 公证（Notarization）** | macOS 必须签名并公证，否则无法正常安装运行 | 交付硬要求；需开发者账号与证书预算 |
| **权限引导** | 屏幕录制/辅助功能/剪贴板等需用户首次授权 | 需设计**友好的授权引导流程**，拒绝授权时明确降级说明 |
| **隐私合规** | 应用沙盒/隐私清单（Privacy Manifest） | 需声明数据用途；坚持「不采集」可简化合规 |
| Linux（后续） | 各发行版差异大 | **不进 MVP/近期**，Phase 3+ 评估 |

### 8.3 跨平台产品原则

1. **功能承诺按平台区分**：文档中标明「Win ✅ / mac ✅ / mac 降级 ⚠️」，避免用户预期落差。
2. **交互随平台习惯**：mac 遵循菜单栏与手势习惯，Win 遵循托盘与快捷键习惯。
3. **同一入口、同一模块体系**：跨平台只是「适配差异」，不是「两套产品」。

## 9. 路线图

| 阶段 | 一句话目标 | 核心交付 | 验收点 |
| --- | --- | --- | --- |
| **Phase 1 · 效率套件 MVP** | 做出「能打动大众」的最小组合并**双平台一键安装** | 统一入口 + 桌面整理(基础) + 便签/待办 + 剪贴板 + 工具箱(通用子集) | MVP 验收清单 A1–A12 全通过 |
| **Phase 2 · 效率增强** | 补齐高频生产力模块 | 快速启动/全局搜索 + 截图套件(标注/贴图/OCR) + 文件处理(批量改名/去重/磁盘分析) | 各模块独立可用；新增模块不改框架 |
| **Phase 3 · 系统与专业** | 强化系统级与专业能力，形成付费点 | 系统优化/增强 + 安全隐私(脱敏/加密/密码管理) + 媒体/PDF + 官方扩展包(L2) | Pro 分层上线；L2 扩展机制跑通 |
| **Phase 4 · 生态与商业化** | 从"工具"走向"平台" | 插件市场(L3) + 账号/可选同步 + 商业化闭环 | 第三方插件可上架；商业收入模式验证 |

> **节奏原则**：**每一阶段都要能独立交付、可装机、可被用户用起来**；不做"一次性交付大而全"，避免长期无法上线。
