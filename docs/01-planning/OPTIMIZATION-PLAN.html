战略性结论：项目历史已经替我们走过一次弯路 —— V42 曾尝试「桌面为主、摘掉侧栏」，你 09-19 复盘时改回「保留主窗口作模块宿主 / 控制台」，V45 已恢复。把桌面上的工具、工作台、桌面整理与主窗口同时保留，并非重复，而是「顺手做 vs 完整办」两个场景的正确分工。本轮要做的是把这条分工说清、做显、自动化。
  • 核心差距一（智能自动整理）：现有整理引擎按类别分组、增量补位、保留用户布局，但盒内未按使用频率 / 时间排序，也无「桌面内容变化时自动把新条目安好」的触发。

  • 核心差距三（视觉一致）：桌面三件套与主窗口是两套风格语言（深色实心 vs light/dark 主题），未共用统一的收纳盒视觉 token。

2战略定案：双面共存 + 归属规则

「方便，而不是全面」是产品命名主张。桌面层就是「方便」的兑现，主窗口则是「很多场景天生需要空间与持续性」的兑现。两不是重复，是互补。

2.1 为什么不能「全部塞进桌面、取消主窗口」

桌面的强项是随手够得着，弱项是不装大内容。分栏类工具（JSON 格式化、文本对比、Cron 描述）在抽屉里已经要「铺满」，再并进设置中心、命令面板、桌面整理控制台、布局备份这类「需要反复进出 / 需要完整画布」的页面，桌面会被撑成第二个任务栏。抽屉的核心设计「装得下一个真实工具」本身就说明：工具需要空间，而空间不该都堆在桌面上。

2.2 归属判定规则（一条即可决策）

判定这个任务在 10 秒内能完成吗？需要空间 / 持续 / 管理吗？
→ 是桌面：随手用一下，就地完成放在桌面层
→ 否控制台：完整界面 / 更多空间 / 可反复进出放进主窗口
功能桌面（顺手面）主窗口（控制台）归属依据
效率工具抽屉「工具」页签就地打开动工具箱模块，完整界面，`在控制台打开` 出口同一注册表契约，桌面轻用 / 控制台必用完整版；工具较复杂时一键升格
工作台顶部今日贴条 + 抽屉快捷入口工作台模块（日历/计划/笔记聚合）贴条看概览，完整聚合与编辑进控制台
桌面整理桌面格子 + 右键「打开 Handy 桌面整理」桌面整理控制台（管理/布局备份/诊断）呈现层在桌面，管理与排布配置进控制台
设置 / 命令面板 / 搜索快捷键直达 / 抽屉入口设置中心 + 全局命令面板低频、偏好性，天然在控制台
一句话给用户：「桌面上顺手用，控制台里完整办 —— 同一个工具，在这两边是同一份手，不是两份。开关在地桌面时快，需要多一点空间时点『在控制台打开』就过去。」

3目标架构：窗口模型与数据一致性

⚙️ 桌面层（极致顺手）

  • 智能格子：语义收纳盒 + 盒内智能排序 + 自适应列数
  • 右侧抽屉：工具 / 快捷 / 系统入口
  • 顶部贴条：今日日历 / 待办 / 快捷
  • 自动触发：桌面内容变化 → 新条目智能安置

🖥️ 主窗口（按需工作室）

  • 模块宿主侧栏 + 各模块完整视图
  • 设置中心 / 命令面板 / 全局搜索
  • 桌面整理控制台（管理 / 备份 / 诊断）
⇅ 共享同一份数据层（grid_boxes / grid_meta / notes / todos / settings）与同一套命令 · 模块注册契约

3.1 数据一致性铁律（延续 V46 不变量）

  • 桌面层与主窗口绝不各持一份数据；挂件窗只能发事件，主窗口的 store 每窗口独立（ADR-8），跨窗靠 Rust 命令 + `handy:navigate`。
  • 布局几何只来自 Rust，前端只画。新增的「盒内排序 / 自适应」同样落到 Rust 引擎，前端不得另起一套布局算法（避免「两套布局」回归）。
  • 新增任何浮层组件必须登记命中区白名单（V47 强制动作）。

4智能自动整理引擎（核心详设）

目标：每次整理（含自动触发）都能让桌面展出「最佳布局」——归类语义、盒内有序、自适应密度、新文件自动进场，且绝不动用户文件、绝不破坏用户已摆好的布局。

4.1 现状基线（Rust grid.rs）

arrange_group_of(item) // .lnk→None(进竖条)；文件夹→"文件夹"；其余按扩展名类别 arrange_group_rank() // 文件夹=0，其余类别=2，"其他"=3 auto_arrange_inner() // 扫两个桌面根 → 按类别分组 → 只登记引用 → dissolve_auto_boxes → layout_all_boxes(Fill) layout_all_boxes(Fill) // 增量：已摆好的格子不动，只安置新建/重叠/越界 LayoutMode::Reset // "重新重置整理"：全量按规则重排，覆盖用户手动调整

4.2 增强设计

A · 归类细化（借鉴腾讯 4 类 / 360 收纳盒）

收纳盒收录当前来源处置
文件夹桌面文件夹（含 Handy 历史容器）is_dir保留
图片png/jpg/jpeg/gif/webp/svg/bmp/icocategory=图片保留
文档doc/docx/xls/ppt/pdf/txt/md…category=文档保留
压缩包 / 安装包zip/rar/7z/tar.gz；exe/msi独立类别保留
快捷方式.lnk + 系统入口（此电脑/回收站/用户文件）左侧未归类竖条保留不进格子
媒体 / 其他音视频、其它扩展名"其他"可细分「媒体」盒
细化的主价值是语义一致：用户一眼知道自己桌面有什么。单类别条目过少（如某类别只有 1 个文件）时，不要开一个只有一项的盒子 —— 合并进「其他」，避免把桌面切成碎片。

B · 盒内智能排序（本轮最该先做的「最佳布局」）

同一盒子里，条目不再按登记先后堆叠，而按重要性优先级排：

优先级排序键数据来源效果
1用户手动置顶 / 已钉grid_items.pinned / 拖拽顺序常用项永远在最前
2最近使用（frecency）打开事件埋点（可选）高频项上浮
3修改时间（新在前）文件 mtime（扫描可得）新文件置前
4名称（稳定兜底）文件名其余按名排，可预期

落地位置：Rust register_item 与 layout_all_boxes 之间，为每个盒子按上述键生成 sort；前端盒子内渲染 read 该 sort。纯逻辑可单测（复用现有 mtime 扫描，不含埋点也能先按「mtime + 置顶」排序）。

C · 自适应布局（随工作区密度排布）

  • 按挂件窗可用宽高决定列数与每盒容量：宽屏多用列、窄屏换行展开，避免「一列排到桌面底外」（历史缺陷）。
  • 盒子尺寸按内容自动撑开（已有能力），超高时盒内滚动，不挤压其它区域。
  • 镜像流布（自右向左）+ 挂件占右上，保持 V47 的整列保留规则。

D · 自动触发（每次变化都保持最佳）

新建/下载/拖入的条目落到桌面后，不打扰用户地把新条目安置进对应盒子（沿用 `LayoutMode::Fill`，新条目增量归位、已摆好的不动）。这是「每次整理都自动展示最佳布局」的轻度自动化 —— 不做全量重排（那会覆盖用户手动布局）。
触发源建议行为实现
桌面条目变化（新建 / 移动 / 下载完成）增量安置新条目Rust 桌面变更轮询或 SHChangeNotify，去抖后调 Fill 布局
一键整理（手动）全量扫描 + 增量安置（保留用户布局）现状保留
「重新重置整理」全量按规则重排现状保留（LayoutMode::Reset）
切换分辨率 / 显示器触发一次自适应布局监听 display change

E · 防回归不变量（无论怎么自动化都不能破坏）

  • I1 `Off ⇒ 原生图标可见`；I3 挂件窗恒可见；I4 窗口显隐与图标显隐同源；I5 绝不移动用户文件。
  • 自动触发只增量安置新条目，绝不覆盖用户已摆好 / 已手动移出的格子。
  • 自动安置前必须读 sync_dismissed（用户移出名单）：刚被用户移出的条目不自动塞回。
  • 任何自动布局后跑一次 z_verdict 复验（V47）。

5重复内容去重与归属收敛清单

「清理重复」前提是分清哪些是真重复（该删），哪些是同一份数据两种展示位（该说清、不该删）。

位置类型处置理由
抽屉「工具」页签 ⇄ 主窗口「工具箱」模块同一注册表契约保留，加"双面分工"说明，`在控制台打开`出口统一轻用 vs 完整用，职责不同、数据唯一
抽屉「快捷」⇄ 底部 Dock同源 quicklinks保留，两处只增删改同一份数据抽屉找 / Dock 用
「工作台」模块 ⇄ 顶部贴条同一 notes/todos保留，贴条看概览，模块做聚合编辑概览 vs 完整
便签：桌面便签窗 + 工作台便签面板同 notes 表保留多窗口编辑（V08 设计）便签天然悬浮
历史遗留「系统 / 快捷方式」空格、`::%` 残留登记数据残留确认由 dissolve_auto_boxes 幂等清理真重复，清理
「桌面整理」双入口（侧栏 + 桌面右键）同一视图保留两入口自然反射（桌面右键）+ 固定导航
结论：本项目的「重复」绝大多数是有意为之的场景分工，真正的清理点是「让用户一眼看懂为什么有两个位置」—— 用归属说明卡 + 统一的『在控制台打开 / 收起』出口来兑现，而不是删功能。

6界面风格 / 布局优化（借鉴腾讯 / 360 整理）

6.1 怎么借鉴「社整理」的观感，又守住本项目底线

腾讯 / 360 桌面整理的招牌是半透明毛玻璃收纳盒 + 分类色图标。但本项目 V46 用户明确否掉半透明（「工都要不要透明了，透明有问题」「很难清楚的操作」）—— 那是在高对比壁纸上的真实可用性问题。所以借鉴其收纳盒组织逻辑与分类色彩语言，不做它的透明玻璃，保持深色实心高可读性。
可取点（借鉴）本项目落地
分类收纳盒：一眼归类的语义容器保留格子；盒内按 4.2-B 智能排序；盒子浅色分类色块 + 图标统一
分类用色识别（图片粉 / 文档蓝 / 压缩黄…）给每个分类配一个浅底 chip 色（沿用 ToolGrid / toolCategories 的色值语言）
自动整理零门坎新增「自动整理」偏好开关 + 内容变化自动安置（路线图 B）
图标批量 / 大图标盒内条目图标沿用系统图标，标题字号统一上调（V45 方向）

6.2 统一视觉 token（消除桌面 ↔ 控制台割裂）

  • 建立共享的「收纳盒」设计原语：圆角、浅分类色、图标容器、条目行 —— 桌面格子与管理页复用同一套，杜绝两套语言。
  • 桌面工具本体 bg-neutral-950 实心 + 圆角；控制台工具页保持 light/dark 主题。两者通过分类色 chip 与图标对齐。
  • 首屏信息密度：工具箱、工作台首屏克制，核心功能前置，非核心收纳到底部（沿用你的偏好）。
